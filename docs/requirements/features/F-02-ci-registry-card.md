# F-02. Реестр и карточка КЕ

> Статус: draft · 2026-10-10 · Приоритет: Must

## 1. Цель
Реестр — основной рабочий экран [S1 ¶25]: пользователь за секунды находит нужные КЕ, видит, что требует внимания, и выгружает выборку. Карточка показывает все данные КЕ и позволяет их вести. Фича решает задачу, если:
- на объёмах NFR-1 реестр и карточка открываются за 1 с, поиск и фильтр срабатывают за 3 с (NFR-2);
- КЕ с просроченным мероприятием видна в реестре без открытия карточки.

## 3. User stories
Роли настраиваются (README §5), поэтому story называет право, а не роль. Какие роли получают право по умолчанию — таблица §2 [ревью ВП 2026-10-14].

- **F-02.US1** — Как пользователь, я хочу видеть реестр КЕ доступных мне категорий и типов с поиском и фильтрами, чтобы быстро найти нужную КЕ.
- **F-02.US2** — Как пользователь, я хочу, чтобы мои фильтры, колонки, сортировка и размер страницы запоминались, чтобы не настраивать реестр при каждом входе.
- **F-02.US3** — Как пользователь, я хочу сохранять личные представления, а с правом «Публикация общих представлений реестра» — и общие, чтобы команда работала с одинаковыми выборками.
- **F-02.US4** — Как пользователь, я хочу, чтобы в реестре были подсвечены КЕ с просроченными и близкими сроками, чтобы сразу видеть, что требует внимания.
- **F-02.US5** — Как пользователь с правом «Экспорт реестра», я хочу выгрузить реестр в Excel или CSV с текущими фильтрами и колонками, чтобы предъявить его инспектору или обработать.
- **F-02.US6** — Как пользователь с правом на нужное действие над КЕ (изменение, переход, мягкое удаление, создание мероприятий), я хочу выполнить его сразу над многими выбранными КЕ, чтобы не менять сотни КЕ по одной. [B2-1b]
- **F-02.US7** — Как пользователь с правом Create на тип КЕ, я хочу создать КЕ этого типа с подставленным кодом и значениями по умолчанию, чтобы завести КЕ быстро и без ошибок.
- **F-02.US8** — Как пользователь с правом Create на тип КЕ, я хочу получать предупреждение о возможном дубле при создании КЕ, чтобы не заводить одну КЕ дважды.
- **F-02.US9** — Как пользователь с правом Update на тип КЕ, я хочу редактировать карточку с подсказками и проверкой значений, чтобы данные были корректными.
- **F-02.US10** — Как пользователь с правом Update на тип КЕ, я хочу видеть, каких обязательных полей не хватает неполной КЕ, чтобы привести её в порядок.
- **F-02.US11** — Как пользователь с правом Update на тип КЕ, я хочу, чтобы при одновременном редактировании мои и чужие изменения не терялись, чтобы данные не затирались молча.
- **F-02.US12** — Как пользователь с правом Update на тип КЕ, я хочу вести матрицу ответственности КЕ, чтобы было понятно, кто отвечает за КЕ и кого уведомлять.
- **F-02.US13** — Как пользователь с правом Update на тип КЕ, я хочу указывать внешние контакты КЕ — поставщика, производителя, подрядчика и их контактных лиц, — чтобы быстро с ними связаться.
- **F-02.US14** — Как пользователь с правом Update на тип КЕ, я хочу указывать внешние идентификаторы КЕ, чтобы сопоставлять её с записями внешних систем.
- **F-02.US15** — Как пользователь, я хочу листать КЕ выборки прямо из карточки («5 из 13»), чтобы просматривать их подряд [S2].
- **F-02.US16** — Как пользователь, я хочу открыть карточку КЕ на телефоне по ссылке — в сети предприятия и после входа в систему, — чтобы посмотреть данные на месте [P-22].
- **F-02.US17** — Как пользователь с правом Update на текущий тип КЕ и Create на новый, я хочу сменить тип ошибочно заведённой КЕ в пределах категории, чтобы не терять её историю и связи. [B2-5a]
- **F-02.US18** — Как пользователь с правом «Отчёт о выбывших сотрудниках», я хочу видеть, в каких КЕ и в каком качестве указаны уволенные сотрудники и заблокированные пользователи, чтобы вовремя их заменить [ревью ВП 2026-10-14].

## 4. Бизнес-правила

**Доступ**
- **F-02.BR1** — Реестр и карточка показывают только КЕ тех типов, на которые у пользователя есть право Read, в пределах ограничения по записям его ролей. Права ролей объединяются [INV-8, S1 ¶25, R8a]. Фильтр по типам предлагает только эти типы.
- **F-02.BR2** — Если КЕ не существует или у пользователя нет к ней доступа, ответ одинаковый: «КЕ не найдена или нет доступа». Так нельзя узнать, существует ли недоступная КЕ. [PROPOSAL]
- **F-02.BR3** — Права на действия с КЕ:
  - создать — только КЕ действующего типа, на который есть право Create;
  - изменить — с правом Update;
  - мягко удалить — с правом Delete (F-03.BR23).

**Реестр: список, поиск, фильтры**
- **F-02.BR4** — Реестр выводит КЕ постранично: 25, 50 или 100 строк, по умолчанию 50 [S1 ¶14, ¶25]. Над списком — число найденных КЕ.
- **F-02.BR5** — Колонки и сортировка: [PROPOSAL: колонки и сортировка по умолчанию]
  - колонки по умолчанию: Код, Наименование, Тип, Статус, Критичность, Организация-владелец, Местоположение;
  - пользователь включает и выключает колонки, меняет их порядок и ширину;
  - доступны базовые поля и настраиваемые поля типов, выбранных в фильтре; у КЕ других типов такая колонка пуста;
  - сортировать можно по любой колонке, кроме многозначных; по умолчанию — по Наименованию.
- **F-02.BR6** — Быстрый поиск срабатывает от 2 символов и не учитывает регистр. Он ищет вхождение в Код, Наименование, Описание, внешние идентификаторы и строковые поля. Результат — не позже 3 с на объёмах NFR-1 (NFR-2). [PROPOSAL: состав полей поиска]
- **F-02.BR7** — Фильтры [S1 ¶25; PROPOSAL: состав]:
  - категория, тип, статус, критичность;
  - организация — владелец или «общая для»;
  - подразделение-владелец — с вложенными [B2-4a];
  - местоположение — с вложенными;
  - ответственный сотрудник и роль ответственности; быстрый фильтр «Мои КЕ» — КЕ, где я есть в матрице ответственности;
  - статус срока: «есть просроченное», «есть близкий срок» — по мероприятиям и контролируемым датам;
  - «неполная», «есть изменения на согласовании»;
  - период создания, период изменения;
  - документы КЕ (F-10): название документа содержит заданный текст; вид документа [ревью ВП 2026-10-14];
  - любое поле с оператором, который зависит от типа данных:
    - строка — содержит, начинается с, равно, пусто [ревью ВП 2026-10-14];
    - число и дата — равно, больше, меньше, период, пусто;
    - значение справочника, сотрудник, контрагент — одно из;
    - флаг — да или нет.

  Разные фильтры объединяются через «И», значения внутри одного фильтра — через «ИЛИ».
- **F-02.BR8** — Фильтры, колонки, сортировка и размер страницы запоминаются для пользователя автоматически. При следующем входе они восстанавливаются, в том числе на другом компьютере [S1 ¶25, domain-model §8].
- **F-02.BR9** — Сохранённое представление — это название, фильтры, колонки, сортировка и размер страницы [ревью ВП 2026-10-14]. Оно бывает личным или общим [domain-model §8]. [PROPOSAL: право публикации и кто меняет общее представление]
  - Личное представление видит только владелец.
  - Общее видят все, но каждый — только доступные ему КЕ (BR1).
  - Публиковать общие представления может пользователь с правом «Публикация общих представлений». По умолчанию это администратор системы, администратор конфигурации и менеджер конфигураций.
  - Менять и удалять общее представление может его автор и администратор системы.
- **F-02.BR10** — Мягко удалённые КЕ в реестре не показываются. Пользователь с правом Delete на тип видит их через фильтр «Мягко удалённые» (F-03.BR24).

**Подсветка**
- **F-02.BR11** — Строка КЕ подсвечивается [S1 ¶15, P-8]:
  - **красным** — есть хотя бы одно просроченное мероприятие или прошедшая контролируемая дата;
  - **бледно-жёлтым** — просроченных нет, но до срока мероприятия или контролируемой даты осталось не больше N дней. N — настройка системы «близкий срок», по умолчанию 7.

  Если подходят оба цвета, строка красная. Подсветка — только у КЕ в эксплуатационных статусах, не удалённых [domain-model §9.2]. Вместе с цветом показывается значок с подсказкой, потому что цвет не может быть единственным признаком (NFR-8). [PROPOSAL: значение N по умолчанию]
- **F-02.BR12** — В строке реестра есть значки «неполная» и «есть изменения на согласовании».

**Экспорт**
- **F-02.BR13** — Экспорт в CSV и Excel (.xlsx) выгружает все КЕ текущей выборки — все страницы, а не только открытую [S1 ¶25]. Колонки и сортировка — текущие. [PROPOSAL: формат файла]
  - Колонка «Код» выгружается всегда.
  - Значения — как в интерфейсе: названия записей справочников, ФИО.
  - Дата-время — в часовом поясе пользователя; пояс указан в заголовке колонки.
  - CSV — в кодировке UTF-8 с BOM и с разделителем «;», чтобы Excel открывал файл без настройки.
- **F-02.BR14** — Объём и доставка файла экспорта:
  - в одном файле — до 500 000 строк, то есть весь объём NFR-1. Если в выборке больше, экспорт не запускается: система сообщает число КЕ и просит уточнить фильтр [ревью ВП 2026-10-14];
  - экспорт 100 000 строк — не дольше 1 мин (NFR-2);
  - файл готовится на сервере, а пользователь тем временем может работать дальше;
  - когда файл готов, браузер скачивает его сам, если страница KE открыта. В колокольчик приходит уведомление: имя файла, время запуска, время готовности и ссылка для скачивания [ревью ВП 2026-10-14];
  - на сервере файл хранится 24 ч и только для скачивания — на случай, если пользователь закрыл страницу до готовности. Скачать его может только тот, кто запускал экспорт. Через 24 ч файл удаляется.

  [PROPOSAL: 500 000, срок хранения 24 ч]
- **F-02.BR15** — Экспорт доступен ролям с правом «Экспорт реестра» (README §5) и выгружает только доступные пользователю КЕ. Каждый экспорт пишется в контрольный след: кто, когда, какой фильтр, сколько строк (F-11).

**Массовые операции** [B2-1b]
- **F-02.BR16** — Пользователь выбирает КЕ в реестре: отдельные строки или «все по фильтру», до 1 000 КЕ за раз. Затем он выполняет одну операцию из списка:
  - изменить значение поля — кроме контролируемых полей и полей «только для чтения в интерфейсе»;
  - назначить сотрудника в роль ответственности основным или замещающим либо заменить одного сотрудника другим во всех ролях;
  - выполнить переход статуса, если он не контролируемый и не требует ЭП;
  - мягко удалить — с одной причиной для всех;
  - выгрузить выбранные (BR13);
  - создать разовое мероприятие (F-05) [B2-1b]. У каждой выбранной КЕ появляется своё мероприятие с одинаковыми названием, видом, плановой датой (сегодня или позже, INV-19) и настройками: результат, ЭП, вложение, уведомления, задачи в таск-трекере, чек-лист. Ответственный задаётся одним из двух способов:
    - один сотрудник для всех КЕ;
    - роль ответственности: у каждой КЕ ответственным становится её основной сотрудник в этой роли. Если у КЕ такая роль не заполнена, мероприятие для неё не создаётся и попадает в отчёт (BR17).

    Ограничение «Только указанные ответственные» (F-01.BR11) проверяется для каждой КЕ отдельно. Нужно право «Создание и настройка мероприятий КЕ» (README §5). Пример: мероприятие «Установить обновление безопасности» до 15.11 для 200 серверов, ответственный — «ИТ-сопровождение» каждого сервера.
- **F-02.BR17** — Каждая КЕ обрабатывается отдельно, с проверкой прав, условий и правил полей. Если для части КЕ операция невозможна, остальные всё равно меняются. Итог — отчёт: сколько КЕ изменено и по каждой неизменённой КЕ — причина. Пример: из 120 серверов переход «Отправить на обслуживание» выполнен у 117; у трёх КЕ статус «Списана», такого перехода из него нет.
- **F-02.BR18** — В регулируемой категории массовая операция требует одну причину изменения для всех КЕ. В контрольный след каждая КЕ пишется отдельной записью с общим номером операции (F-11).
- **F-02.BR19** — Ход массовой операции [ревью ВП 2026-10-14]:
  - операция выполняется на сервере. Пока она идёт, пользователь видит окно с ходом: сколько КЕ обработано из скольких и сколько с ошибками;
  - окно можно закрыть, можно уйти на другую страницу или закрыть браузер — операция не прервётся. Окно сообщает об этом пользователю;
  - кнопка «Остановить» прекращает обработку оставшихся КЕ. Уже изменённые КЕ остаются изменёнными, это видно в отчёте;
  - по завершении отчёт (BR17) показывается в окне, сохраняется в системе и приходит уведомлением в колокольчик со ссылкой. В разделе «Мои дела» отчёт доступен 30 дней;
  - операция над 1 000 КЕ завершается не дольше чем за 1 мин.

  [PROPOSAL: срок хранения отчёта, время выполнения]

**Создание КЕ**
- **F-02.BR20** — Пользователь выбирает тип, и карточка открывается по шаблону типа (F-01) со значениями по умолчанию: [PROPOSAL: организация и подразделение по умолчанию]
  - Наименование — название типа [S2];
  - Организация-владелец — организация сотрудника пользователя;
  - Подразделение-владелец — подразделение сотрудника пользователя [B2-4a];
  - статус — начальный (F-03.BR4).
- **F-02.BR21** — Код КЕ [P-12, INV-1; PROPOSAL: формат]:
  - уникален в установке без учёта регистра, с учётом мягко удалённых КЕ;
  - допустимы буквы (латиница и кириллица), цифры и знаки «-», «_», «.», «/», без пробелов, до 50 символов;
  - если у типа есть шаблон кода (F-01.BR12), код подставляется автоматически, и пользователь может заменить его своим [B2-2a].
- **F-02.BR22** — Перед созданием система ищет возможные дубли: КЕ того же типа с тем же Наименованием (без учёта регистра и пробелов по краям), включая мягко удалённые [INV-9]. [PROPOSAL: что показывать о недоступных КЕ]
  - Если дубли нашлись, система показывает до 5 найденных КЕ со ссылками (BR42). Пользователь выбирает «Всё равно создать» или «Отмена».
  - КЕ, которые пользователю не видны, не раскрываются: система лишь сообщает, что совпадения есть среди недоступных ему КЕ.
  - Для мягко удалённой КЕ пользователю с правом Delete предлагается восстановить её (F-03.BR26).

  Совпадение поля «Уникальное в типе» — не предупреждение, а запрет (F-01.BR23) [B2-3a].
- **F-02.BR23** — При первом сохранении новой КЕ система спрашивает: «Сохранить Baseline», «Сохранить без Baseline», «Отменить сохранение» [S1 ¶17, P-15]. Вопрос задаётся только пользователю с правом «Создание baseline» (README §5); остальные сохраняют КЕ без вопроса [PROPOSAL]. Подробности — F-09.

**Карточка и редактирование**
- **F-02.BR24** — Что показывает карточка:
  - поля по шаблону типа (F-01);
  - плашки состояния КЕ:
    - «Есть изменения на согласовании» — с разницей «было → станет» [P-4, F-08];
    - «Неполная» — с перечнем незаполненных обязательных полей;
    - «Мягко удалена» (F-03.BR24);
  - разделы: связи (F-04), мероприятия (F-05), документы (F-10), ответственные, внешние контакты, внешние идентификаторы, baseline (F-09), связанные КЕ и анализ влияния (F-22), история (F-11, по праву «Просмотр истории КЕ»).
- **F-02.BR25** — Каждое поле проверяется по правилам своего типа данных (F-01.BR18). Ошибка показывается у поля с объяснением. При сохранении карточки в интерфейсе все обязательные поля должны быть заполнены [INV-6, S1 ¶7]. Если КЕ неполная, система подсвечивает незаполненные поля и не сохраняет карточку, пока их не заполнят. Исключения — поля «только для чтения в интерфейсе» (F-01.BR24) и поля, скрытые по условию (F-01.BR36). Полноту КЕ не требуют [PROPOSAL]:
  - переходы статуса — кроме условия «заполнены указанные поля» (F-03.BR11);
  - массовые операции (BR16);
  - действия в разделах карточки: связи, мероприятия, документы, ответственные, внешние контакты, внешние идентификаторы;
  - частичное обновление через API и импорт (F-01.BR21).
- **F-02.BR26** — Значение могло стать недоступным для выбора: недействующая запись справочника, уволенный сотрудник, недействующий контрагент. Такое значение остаётся в КЕ с пометкой. Если поле не меняли, при сохранении карточки значение менять не нужно [INV-23].
- **F-02.BR27** — Изменение контролируемого поля при включённом контроле изменений не применяется сразу: создаётся запрос на изменение (F-08). Пока запрос на согласовании, контролируемые поля КЕ изменить нельзя: второй запрос не создаётся [INV-12]. Неконтролируемые поля сохраняются сразу, в том числе пока запрос на согласовании [P-4]. В регулируемой категории сохранение требует причины изменения [P-5, F-08].
- **F-02.BR28** — Одновременное редактирование: другой пользователь мог сохранить КЕ, пока карточка была открыта. Тогда сохранение отклоняется с сообщением, кто и когда изменил КЕ. Введённые значения не теряются: пользователь видит, какие поля изменились, и может перенести свои значения в обновлённую карточку. Молча затереть чужие изменения нельзя. [PROPOSAL]
- **F-02.BR29** — У каждой КЕ — постоянная ссылка. Она не меняется при смене кода и наименования. Ссылку используют уведомления и задачи в таск-трекерах [S1 ¶11]. Ссылка сама по себе доступа не даёт [ревью ВП 2026-10-14]:
  - карточка открывается только после входа в систему и только при праве Read на КЕ (BR1, BR2);
  - если пользователь не вошёл, система показывает страницу входа, а после входа открывает карточку.
- **F-02.BR30** — Если карточка открыта из реестра, в ней можно перейти к предыдущей и следующей КЕ текущей выборки. Видна позиция: «5 из 13» [S2].
- **F-02.BR31** — Сменить тип КЕ можно на другой действующий тип той же категории [B2-5a]:
  - нужны право Update на текущий тип и право Create на новый;
  - базовые поля и поля категории сохраняются;
  - значения полей старого типа уходят из карточки и остаются в истории КЕ;
  - поля нового типа получают значения по умолчанию; если обязательное поле осталось пустым, КЕ становится неполной;
  - статус, связи, мероприятия, документы и история сохраняются;
  - мероприятия по обязательным шаблонам нового типа добавляются (F-05);
  - если после смены типа связи КЕ не соответствуют допустимым парам, система предупреждает до смены, а потом помечает такие связи (F-04.BR5);
  - если значение поля категории с признаком «Уникальное в типе» уже есть у КЕ нового типа, тип не меняется; система называет эту КЕ (F-01.BR23);
  - смена типа пишется в контрольный след; в регулируемой категории нужна причина; поле «Тип» можно отметить контролируемым (F-01.BR25).

  Сменить категорию КЕ нельзя: у другой категории другая статусная модель.
- **F-02.BR32** — Код КЕ можно изменить по праву Update. Старый код освобождается, изменение пишется в контрольный след. Постоянная ссылка и системный ID не меняются. [PROPOSAL]
- **F-02.BR33** — Подразделение-владелец — подразделение организации-владельца КЕ [B2-4a]. Если сменить организацию-владельца, поле очищается. По этому полю работает ограничение роли «только моё подразделение»: КЕ моего подразделения и вложенных (F-13).

**Матрица ответственности** [P-10, domain-model §4.2]
- **F-02.BR34** — Строка матрицы:
  - роль ответственности — запись справочника «Роли ответственности»;
  - сотрудник;
  - «основной» или «замещающий».

  В одной роли ответственности — не больше одного основного, замещающих — сколько угодно [domain-model §4.2]. Один сотрудник не повторяется в одной роли [PROPOSAL].
- **F-02.BR35** — Назначить можно только работающего сотрудника [domain-model §2.3], с учётом ответственных типа и флажка «Только указанные ответственные» (F-01.BR11). Уволенный сотрудник остаётся в матрице с пометкой «Уволен», пока его не заменят. Такие КЕ показывают отчёт о выбывших сотрудниках (BR43) и качество данных (F-21).
- **F-02.BR36** — Изменения матрицы ответственности пишутся в историю КЕ. Матрицу можно отметить контролируемой как базовое поле (F-01.BR25).

**Внешние контакты** [S2, domain-model §4.6]
- **F-02.BR37** — Строка: роль контрагента, контрагент, контактное лицо, примечание. Контактное лицо выбирается только из контактных лиц этого контрагента. Выбрать можно только действующих контрагентов и контактных лиц (F-19.BR23). Контрагенты и контактные лица — встроенный справочник (F-19.BR21–BR24); заказчик может заполнять его из своих систем через API (F-19.BR28).

**Внешние идентификаторы** [W-6a, domain-model §4.1]
- **F-02.BR38** — Строка: система-источник и значение. Система-источник — запись простого справочника «Системы-источники». Пара «система-источник, значение» уникальна в установке. Примеры: Zabbix — 10084; AD — srv-db-01.corp.local. [PROPOSAL: справочник «Системы-источники»]

**Телефон, время, скорость**
- **F-02.BR39** — Карточка КЕ работает на экране шириной от 360 px (NFR-6, P-22). На телефоне можно открыть карточку по ссылке и прочитать все разделы. Подтверждение мероприятия на телефоне — F-05. Редактировать карточку на телефоне не требуется. С телефона KE доступна так же, как с компьютера: из сети предприятия (КСПД) или через VPN заказчика, после входа в систему (BR29). Сетевой доступ организует заказчик при развёртывании; система не проверяет, откуда подключён телефон [ревью ВП 2026-10-14].
- **F-02.BR40** — Дата-время в реестре и карточке показывается в часовом поясе пользователя (NFR-11, A-10).
- **F-02.BR41** — Страница реестра и карточка КЕ открываются не дольше 1 с для 95% запросов на объёмах NFR-1 (NFR-2).

**Ссылки на КЕ в сообщениях**
- **F-02.BR42** — Если в сообщении или предупреждении названа КЕ, её код — ссылка на карточку. Ссылка открывает карточку в новой вкладке браузера, чтобы пользователь не потерял несохранённые данные формы. Примеры: список возможных дублей (BR22), сообщение о повторе «уникального в типе» поля (F-01.BR23), отчёт массовой операции (BR17) [ревью ВП 2026-10-12].

**Выбывшие сотрудники**
- **F-02.BR43** — Отчёт «Выбывшие сотрудники в КЕ» [ревью ВП 2026-10-14]. Он показывает, в каких КЕ указаны:
  - уволенные сотрудники;
  - сотрудники, чья учётная запись заблокирована или отключена.

  По каждой строке видны: КЕ (ссылка, BR42), сотрудник, его состояние и с какой даты, в каком качестве он указан:
  - в матрице ответственности — роль ответственности, основной или замещающий;
  - в поле типа «Сотрудник» — название поля;
  - ответственный за запланированное мероприятие (F-05).

  Отдельный раздел отчёта — типы КЕ, где сотрудник есть в списке ответственных типа (F-01.BR11). Правила доступа и действий:
  - отчёт доступен по праву «Отчёт о выбывших сотрудниках» (по умолчанию — администратор системы и менеджер конфигураций) и показывает только доступные пользователю КЕ;
  - отчёт можно отфильтровать по состоянию и выгрузить в Excel;
  - из отчёта можно перейти к массовой замене сотрудника (BR16).

  [PROPOSAL: состав колонок, право и роли по умолчанию]

## 7. Интерфейс (для дизайнера)
- **Реестр.**
  - Строка быстрого поиска; панель фильтров; выбор и настройка колонок; сортировка.
  - Список сохранённых представлений: личные и общие; «Сохранить как…».
  - Число найденных КЕ; постраничный вывод.
  - Подсветка строк со значком (BR11); значки «неполная» и «на согласовании» (BR12).
  - Выбор строк и «все по фильтру»; меню массовых операций; отчёт по итогам операции (BR17).
  - Экспорт в CSV и Excel: ход подготовки, автоматическое скачивание, уведомление с именем файла, временем запуска и готовности и ссылкой (BR14).
  - Окно хода массовой операции с кнопкой «Остановить» (BR19).
  - Отчёт «Выбывшие сотрудники в КЕ» (BR43).
  - Фильтр «Мягко удалённые» — для пользователей с правом Delete.
- **Создание КЕ.**
  - Выбор типа: только действующие типы с правом Create.
  - Форма по шаблону типа.
  - Окно возможных дублей (BR22).
  - Вопрос о baseline (BR23).
- **Карточка КЕ.**
  - Шапка: иконка типа, код, наименование, статус с цветом, критичность, организация, кнопки переходов (F-03).
  - Плашки (BR24).
  - Поля по шаблону.
  - Разделы (BR24).
  - Навигация «5 из 13» (BR30).
  - Действия: изменить код, сменить тип, мягко удалить.
- **Конфликт одновременного редактирования.** Сообщение со списком изменённых полей и возможностью перенести свои значения (BR28).
- **Матрица ответственности, внешние контакты, внешние идентификаторы.** Таблицы с добавлением и удалением строк.
- **Карточка на телефоне** (от 360 px): чтение всех разделов.
- **Предложение дизайнеру** [S2]: кнопка «Доступ» в карточке для администратора — какие роли видят и меняют эту КЕ.

## 8. Не входит
- Графические и настраиваемые дашборды — позже (discovery §5.4).
- Редактирование карточки на телефоне.
- Права на уровне отдельных полей.
- Поиск по содержимому файлов документов и вложений (полнотекстовый). Поиск по названию документа есть (BR7).
- Язык запросов для произвольных выборок (как AQL в Jira Assets).
- Печатные формы карточки — отдельная фича F-32 [ревью ВП 2026-10-14].
- Смена категории КЕ.
- Оперативное состояние КЕ — с интеграцией мониторинга (W-6a, F-31).
