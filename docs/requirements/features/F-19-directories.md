# F-19. Справочники

> Статус: draft · 2026-10-10 · Приоритет: Must
> Источник: D-1a, D-2a [PO 2026-10-10]; комментарий ВП к discovery §5.5 («любой выбираемый параметр — справочник»); P-14; domain-model §1, §2.8; INV-1, INV-22, INV-23; README §5
> Зависит от: F-13 (роли и права) · Используется в: F-01, F-02, F-03, F-04, F-05, F-10, F-12, F-17 · Экраны: появятся у дизайнера

## 1. Цель
Заказчик сам ведёт все списки выбора — без программиста и без поставщика. Фича решает задачу, если:
- администратор конфигурации создаёт простой справочник, наполняет его и использует в настраиваемом поле;
- запись, которая где-то используется, нельзя потерять: её можно только сделать недействующей.

## 2. Роли и права
Права по умолчанию из «Базового ИТ-пакета» (README §5). Право на ведение (создание, изменение, деактивацию и удаление записей) — отдельное для каждого справочника и назначается любой роли (D-2a, BR18).

| Роль | Видит | Ведёт |
|---|---|---|
| Администратор системы | все справочники | создаёт простые справочники; ведёт записи всех справочников |
| Администратор конфигурации | все справочники | создаёт простые справочники; ведёт записи простых справочников, контрагентов и контактных лиц, типы связей (F-04) |
| Менеджер конфигураций | все справочники | контрагентов и контактных лиц |
| Инженер, Согласующий, Аудитор, Наблюдатель | справочники, если раздел «Справочники» доступен роли (F-13) | — |

Организации, подразделения и сотрудников ведёт администратор системы. Правила их ведения и видимость персональных данных сотрудников — в F-13.

## 3. User stories
- **F-19.US1** — Как администратор конфигурации, я хочу создать простой справочник, плоский или иерархический, чтобы использовать его в настраиваемых полях без программиста.
- **F-19.US2** — Как пользователь с правом ведения справочника, я хочу добавлять, переименовывать, упорядочивать и раскрашивать записи, чтобы списки выбора соответствовали практике заказчика.
- **F-19.US3** — Как пользователь с правом ведения справочника, я хочу делать записи недействующими, чтобы их больше не выбирали, а уже сохранённые данные не пострадали.
- **F-19.US4** — Как администратор системы, я хочу дать право на ведение конкретного справочника любой роли, чтобы, например, секретарь вёл контрагентов, а кадровик — должности.
- **F-19.US5** — Как менеджер конфигураций, я хочу вести контрагентов и их контактных лиц, чтобы указывать их во внешних контактах КЕ.
- **F-19.US6** — Как администратор конфигурации, я хочу видеть, где используется справочник или запись, чтобы понимать последствия изменения.
- **F-19.US7** — Как администратор конфигурации, я хочу загрузить записи справочника из Excel или CSV, чтобы не вводить сотни местоположений вручную. [вопрос 8]

## 4. Бизнес-правила

**Раздел и виды справочников**
- **F-19.BR1** — Все справочники находятся в разделе «Справочники» и делятся на простые и встроенные [D-1a]. Встроенные справочники: Организации, Подразделения, Сотрудники, Контрагенты, Контактные лица, Типы связей. Их реквизиты задаёт продукт. Правила ведения встроенных справочников:
  - организации, подразделения, сотрудники — F-13;
  - типы связей — F-04;
  - контрагенты и контактные лица — эта фича.
- **F-19.BR2** — Простой справочник создаёт пользователь с правом настройки конфигурации (по умолчанию — администратор системы и администратор конфигурации) [README §5]. Пример: справочник «Классы защищённости» с записями К1, К2, К3.

**Простой справочник**
- **F-19.BR3** — Код справочника задаётся при создании и не меняется [INV-1]; формат кода — INV-24. Название обязательно и уникально среди справочников без учёта регистра. Пример: нельзя создать справочник «критичность», если уже есть «Критичность». [PROPOSAL: уникальность названия]
- **F-19.BR4** — Признак «Иерархический» можно включить в любой момент: существующие записи становятся корневыми. Выключить признак можно, только если ни у одной записи нет родителя. [PROPOSAL]
- **F-19.BR5** — Системный справочник поставляет продукт или отраслевой пакет. Его нельзя удалить, но записи вести можно — с ограничениями для системных записей (BR12). Признак «Системный» пользователь не меняет [domain-model §1].
- **F-19.BR6** — Несистемный простой справочник можно удалить, только если на него не ссылается ни одно поле (F-01) и ни одна настройка. Вместе со справочником удаляются его записи. Если ссылки есть, система перечисляет поля и настройки, которые ссылаются на справочник. [PROPOSAL]

**Записи**
- **F-19.BR7** — Код записи задаётся при создании, уникален в справочнике и не меняется [INV-1]; формат кода — INV-24.
- **F-19.BR8** — Название записи обязательно. В плоском справочнике оно уникально в справочнике, в иерархическом — среди записей с тем же родителем. Регистр и пробелы по краям не учитываются. Пример: в «Местоположениях» может быть «Этаж 3» и в «Корпусе 1», и в «Корпусе 2», но не дважды в «Корпусе 2». Так в справочнике не появятся дубли вида «Высокая» / «высокая» [ревью ВП 2026-10-10, справочник «Должности»; PROPOSAL: правило уникальности].
- **F-19.BR9** — Родитель записи — запись того же справочника. Запись нельзя сделать дочерней для неё самой или для её потомка. Глубина дерева — не больше 10 уровней. Пример: Площадка «Москва» → Корпус 2 → Этаж 3 → Помещение 214 → Рабочее место 5 — пять уровней. [PROPOSAL: глубина]
- **F-19.BR10** — Запись можно перенести к другому родителю. Код записи и значения, сохранённые в КЕ, при этом не меняются.
- **F-19.BR11** — Порядок записей — порядок в списках выбора. Новая запись встаёт в конец списка, в иерархическом справочнике — в конец среди записей своего родителя.
- **F-19.BR12** — Системную запись можно переименовать, но нельзя удалить или сделать недействующей [INV-22]. Признак «Системная запись» ставит только продукт или пакет. Пример: запись «Действующий» справочника «Статусы документов».
- **F-19.BR13** — Недействующую запись нельзя выбрать в новых данных. Уже сохранённые значения остаются и показываются с пометкой «недействующая». Если поле с такой записью не меняли, при сохранении КЕ менять значение не нужно [INV-23].
- **F-19.BR14** — В иерархическом справочнике вместе с записью недействующими становятся все её потомки. Система показывает их число и просит подтверждения. Запись нельзя сделать действующей, пока её родитель недействующий. [PROPOSAL]
- **F-19.BR15** — Используемую запись удалить нельзя, только сделать недействующей [INV-23]. «Используется» означает, что запись указана в значении поля КЕ, в документе, шаблоне мероприятия, настройке, условии перехода или у сотрудника. Неиспользуемую запись удалить можно.
- **F-19.BR16** — Запись может использоваться в условии перехода, шаблоне мероприятия или настройке. Перед деактивацией такой записи система показывает эти ссылки и просит подтверждения: новыми данными такое условие выполнить будет уже нельзя. Пример: вид документа «Протокол OQ» указан в условии перехода «Ввести в эксплуатацию» категории «Компьютеризированная система». [PROPOSAL]
- **F-19.BR17** — Действие «Где используется»: [PROPOSAL]
  - для записи — число КЕ с этим значением, поля, условия переходов, шаблоны мероприятий и настройки, где она указана;
  - для справочника — поля, которые на него ссылаются.

**Права**
- **F-19.BR18** — Право на ведение — отдельное для каждого встроенного справочника [D-2a] и для каждого простого справочника [вопрос 7]. Это право можно дать любой роли. Пример: роль «Кадровик» получает право на «Должности», а на «Значения подписи» — нет.
- **F-19.BR19** — Право на ведение нового простого справочника сразу получают роли, которым разрешено создавать простые справочники (по умолчанию — администратор системы и администратор конфигурации). [PROPOSAL]
- **F-19.BR20** — Записи справочников видят пользователи, которым доступен раздел «Справочники» (F-13). В полях КЕ пользователь выбирает из действующих записей, даже если раздел ему недоступен.

**Контрагенты и контактные лица** [S2, domain-model §2.8]
- **F-19.BR21** — Контрагент: [PROPOSAL: проверка ИНН и предупреждение о совпадениях]
  - код — не меняется [INV-1];
  - наименование — обязательно;
  - ИНН — необязателен; 10 или 12 цифр;
  - «действует».

  Если ИНН или наименование совпадают с другим контрагентом, система предупреждает, но сохранить можно: у филиалов бывает общий ИНН.
- **F-19.BR22** — Контактное лицо принадлежит ровно одному контрагенту. ФИО обязательно. Телефон — тип «телефон» (domain-model §3.3). E-mail проверяется по формату.
- **F-19.BR23** — Во внешних контактах КЕ (F-02) нельзя выбрать недействующего контрагента, его контактных лиц и недействующих контактных лиц. Уже указанные значения остаются с пометкой.
- **F-19.BR24** — Используемого контрагента или контактное лицо удалить нельзя, только сделать недействующими — как в INV-23.

**Объёмы, загрузка, контрольный след**
- **F-19.BR25** — В справочнике может быть до 50 000 записей. Список записей — с поиском по коду и названию и постраничным выводом [S1 ¶14]. При выборе значения в поле список фильтруется по мере ввода. [PROPOSAL: 50 000]
- **F-19.BR26** — Изменения справочников и записей пишутся в контрольный след как изменение конфигурации: кто, когда, что было, что стало (F-11). Это создание, изменение, деактивация и удаление.
- **F-19.BR27** — Записи простого справочника загружаются из Excel или CSV с колонками «Код», «Название», «Код родителя», «Порядок», «Действует». Запись с существующим кодом обновляется, с новым — создаётся. Строки с ошибками не загружаются и попадают в отчёт, остальные загружаются. [вопрос 8]

## 7. Интерфейс (для дизайнера)
- **Раздел «Справочники».** Список справочников, разделённый на простые и встроенные, с поиском по названию. У справочника видны число записей и признак «системный».
- **Экран простого справочника.**
  - Записи — списком или деревом, с поиском и постраничным выводом.
  - Порядок меняется перетаскиванием.
  - Флажок «Показывать недействующие».
  - Действия: создать, изменить, сделать недействующей или действующей, удалить, «Где используется», загрузить из файла.
- **Форма записи.** Поля:
  - код — система предлагает его из названия транслитерацией;
  - название;
  - родитель;
  - порядок;
  - цвет — из палитры дизайн-системы, с контрастом по NFR-8;
  - «действует».
- **Контрагенты.** У контрагента виден список его контактных лиц.
- **Сообщения:**
  - почему запись нельзя удалить — с перечнем, где она используется;
  - подтверждение деактивации — с числом потомков (BR14) и ссылками из условий (BR16).

## 8. Не входит
- Настраиваемые поля у встроенных справочников — позже (OQ-1).
- Объединение дублей записей с заменой значения во всех КЕ — позже. В v1 дубли предотвращает BR8.
- Многоязычные названия записей (A-4).
- Зависимые списки, где выбор одной записи сужает выбор в другом поле: «Модель» зависит от «Производителя».
- Цвет записи в произвольном формате: только палитра дизайн-системы.
