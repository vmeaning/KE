# F-14. Аутентификация и синхронизация пользователей

> Статус: draft (решения ВП B3 учтены 2026-10-15) · Приоритет: Must — локальный вход, LDAP/AD, синхронизация с каталогом; Should — SSO, 1С:ЗУП (README §7)
> Источник: S1 ¶24; R5a; NFR-5, NFR-9, NFR-13; README §2; domain-model §2.3, §2.4, §9.4; INV-15, INV-21; OQ-3; discovery §3 (21 CFR Part 11 §11.300, Annex 11 §12)
> Зависит от: F-13 · Связано: F-06, F-11, F-12, F-15, F-17, F-20, F-28 · Экраны: появятся у дизайнера

## 1. Цель
Пользователи входят доменным логином и паролем или без пароля через SSO. Сотрудники, учётные записи и роли приходят из AD и 1С:ЗУП сами, и уволенный в кадровой системе сотрудник теряет доступ без участия администратора KE. Фича решает задачу, если:
- сотрудник, которого добавили в группу каталога «KE-Инженеры», входит в KE с ролью «Инженер» не позже следующей синхронизации;
- учётная запись, отключённая в каталоге, не может войти в KE сразу, ещё до синхронизации;
- вход соответствует NFR-9: уникальные учётные записи, политика паролей, блокировка после неудачных попыток, тайм-аут сессии.

## 2. Роли и права
| Действие | Право | По умолчанию |
|---|---|---|
| Войти, сменить свой пароль (локальная учётная запись) | — | все пользователи |
| Сбросить пароль, разблокировать, завершить сессии пользователя | «Пользователи, роли, замещения» | администратор системы |
| Сопоставить группы каталога с ролями (кроме системной роли — BR19) | «Пользователи, роли, замещения» | администратор системы |
| Подключения к каталогу, SSO, 1С:ЗУП; расписание и журнал синхронизаций | «Интеграции, каналы уведомлений, клиенты API» | администратор системы |
| Политика паролей, блокировки и сессий | «Настройки системы и оформление» | администратор системы |
| Загрузка сотрудников и подразделений из файла | «Ведение сотрудников» и «Ведение организаций и подразделений» | администратор системы |

## 3. User stories
Роли настраиваются (README §5), поэтому story называет право, а не роль. Какие роли получают право по умолчанию — таблица §2.

- **F-14.US1** — Как пользователь, я хочу входить по своему логину и паролю — локальному или доменному, — чтобы работать в KE.
- **F-14.US2** — Как пользователь, я хочу входить без ввода пароля, когда я уже вошёл в домен или в корпоративный SSO, чтобы не помнить ещё один пароль [B3-12a].
- **F-14.US3** — Как пользователь с локальной учётной записью, я хочу сменить свой пароль, чтобы выполнять политику безопасности.
- **F-14.US4** — Как пользователь с правом «Пользователи, роли, замещения», я хочу сбросить пароль, разблокировать учётную запись и завершить сессии пользователя, чтобы помочь ему или срочно закрыть доступ.
- **F-14.US5** — Как пользователь с правом «Настройки системы и оформление», я хочу задать политику паролей, блокировки и тайм-аута сессии, чтобы выполнить требования службы ИБ и 21 CFR Part 11.
- **F-14.US6** — Как пользователь с правом «Интеграции, каналы уведомлений, клиенты API», я хочу подключить один или несколько каталогов — AD, в том числе AD нескольких доменов холдинга, или другие LDAP-каталоги — и настроить синхронизацию, чтобы сотрудники и учётные записи появлялись сами [S1 ¶24].
- **F-14.US7** — Как пользователь с правом «Пользователи, роли, замещения», я хочу сопоставить группы безопасности каталога с ролями KE, чтобы права выдавались через привычные группы [S1 ¶24].
- **F-14.US8** — Как пользователь с правом «Интеграции, каналы уведомлений, клиенты API», я хочу загружать сотрудников, подразделения, должности и увольнения из 1С:ЗУП, чтобы оргструктура в KE совпадала с кадровой [S1 ¶24, B3-13a].
- **F-14.US9** — Как пользователь с правом «Интеграции, каналы уведомлений, клиенты API», я хочу видеть журнал синхронизаций с ошибками и не допустить массового отключения учётных записей из-за ошибки в фильтре.
- **F-14.US10** — Как пользователь с правом «Ведение сотрудников», я хочу загрузить сотрудников и подразделения из Excel или CSV, если кадровая система — не 1С:ЗУП.

## 4. Бизнес-правила

**Вход и сессии** [NFR-9]
- **F-14.BR1** — Источник аутентификации учётной записи — один из трёх [domain-model §2.4]:
  - **локальная** — пароль проверяет KE;
  - **LDAP-AD** — пароль проверяет каталог. Такая учётная запись может входить и через SSO, если провайдер возвращает её логин;
  - **SSO** — личность подтверждает внешний провайдер, пароля в KE нет.

  Источник меняет пользователь с правом «Пользователи, роли, замещения», с записью в контрольный след. Пример: локальную учётную запись подрядчика переводят на LDAP-AD, когда ему выдали доменную.
- **F-14.BR2** — Страница входа одна для всех: логин и пароль, а если настроен SSO — кнопка «Войти через <провайдер>». Логин — без учёта регистра. Доменный логин принимается в виде «ivanov», «DOMAIN\ivanov» и «ivanov@domain.ru» и приводится к логину учётной записи. Если подключено несколько каталогов, домен определяет каталог. Логин без домена ищется во всех подключениях; если он есть в нескольких, система просит ввести логин с доменом [PROPOSAL].
- **F-14.BR3** — Сообщения при неудачном входе не раскрывают, существует ли логин [PROPOSAL]:
  - неверный логин или пароль, отключённая учётная запись, учётная запись, заблокированная вручную или за отсутствие входа (F-13.BR20), — «Неверный логин или пароль, или вход для учётной записи закрыт. Если войти не получается, обратитесь к администратору»;
  - после N неудачных попыток подряд с одним и тем же введённым логином — существует он или нет — «Слишком много неудачных попыток. Повторите через 15 мин» (длительность — из BR4).
- **F-14.BR4** — Блокировка после неудачных попыток [NFR-9, Part 11 §11.300(d)]:
  - после 5 неудачных попыток подряд (настройка, 3–20) учётная запись блокируется на 15 мин (настройка, 1–1 440) и разблокируется сама;
  - администратор может разблокировать раньше;
  - счётчик обнуляется после успешного входа;
  - правило действует для всех источников, в том числе LDAP-AD: KE считает свои попытки независимо от политики домена;
  - неудачные попытки подписи (F-12) считаются так же;
  - при блокировке администраторы системы получают уведомление в колокольчик. [PROPOSAL: последние два пункта]
- **F-14.BR5** — Сессия:
  - тайм-аут бездействия — 30 мин (настройка, 5–480). За 2 мин до истечения система предупреждает и предлагает «Продолжить работу». По истечении сессия завершается. Несохранённые изменения в открытой форме теряются, система об этом предупреждает в том же окне. После повторного входа пользователь возвращается на ту же страницу;
  - наибольшая длительность сессии — 12 ч (настройка, 1–24), потом нужен повторный вход [PROPOSAL];
  - одновременно можно работать в нескольких сессиях: вкладки, устройства;
  - «Выйти» завершает текущую сессию.
- **F-14.BR6** — Пользователь с правом «Пользователи, роли, замещения» видит активные сессии учётной записи — время входа, IP-адрес, браузер — и может завершить их [PROPOSAL]. Блокировка и отключение завершают все сессии не позже чем через 1 мин (F-13.BR15).
- **F-14.BR7** — В контрольный след пишутся с IP-адресом и способом входа [domain-model §7.1]: вход, неудачный вход (введённый логин, без пароля), выход, истечение сессии, блокировка и разблокировка, смена и сброс пароля, завершение сессий администратором. Пароли, токены и секреты подключений никогда не попадают в контрольный след и журналы [INV-21].

**Локальные учётные записи**
- **F-14.BR8** — Пароль хранится так, что его не может узнать никто, включая администраторов системы и СУБД. Способ хранения — ADR Архитектора.
- **F-14.BR9** — Политика паролей — настройка системы [NFR-9]. Значения по умолчанию [PROPOSAL]:
  - длина — не меньше 10 символов (8–64);
  - символы — не меньше 3 из 4 групп: строчные, прописные, цифры, спецсимволы;
  - пароль не содержит логин;
  - не совпадает с 5 последними паролями (0–24);
  - срок действия — не ограничен (0–365 дней). Если срок задан, за 7 дней до истечения система предупреждает при входе, а после истечения требует сменить пароль.

  Новая политика действует при следующей смене пароля; новый срок действия — сразу. Рекомендуемые строгие значения для регулируемой среды (discovery §3) даёт руководство администратора (`docs/ops/`); настройки системы в пакеты конфигурации не входят.
- **F-14.BR10** — Новый пароль проверяется по политике. Если правило не выполнено, система называет его: «Не меньше 10 символов», «Совпадает с одним из 5 последних паролей».
- **F-14.BR11** — Временный пароль [B3-14a]. При создании локальной учётной записи и при сбросе пароля система генерирует временный пароль по политике и показывает его администратору один раз. Администратор передаёт его пользователю сам. Задать пароль пользователю вручную администратор не может. Временный пароль действует 72 ч (настройка, 1–168 ч). При первом входе система требует сменить его, без этого работать нельзя.
- **F-14.BR12** — Пользователь меняет свой пароль в профиле: вводит текущий и дважды новый. После смены остальные его сессии завершаются [PROPOSAL].
- **F-14.BR13** — Аварийный администратор [INV-25, PROPOSAL]. В установке всегда есть хотя бы одна активная локальная учётная запись с системной ролью. Последней такой учётной записи нельзя:
  - заблокировать вручную или отключить;
  - сменить источник аутентификации;
  - снять системную роль.

  Временная блокировка после неудачных попыток для неё действует, иначе пароль можно подбирать. Так администратор войдёт, даже если каталог или провайдер SSO недоступны.

**Каталог: AD и другие LDAP-каталоги** (Must)
- **F-14.BR14** — Подключений к каталогу может быть несколько, например по одному на каждый домен AD холдинга [PROPOSAL]. Поддерживаются Active Directory и LDAP v3-каталоги: ALD Pro, FreeIPA, OpenLDAP — у каждого свой набор атрибутов по умолчанию. Параметры подключения:
  - название и адреса серверов по порядку: если первый недоступен, используется следующий;
  - защищённое соединение LDAPS или StartTLS — по умолчанию. Соединение без шифрования — только по явному выбору, с предупреждением, что пароли пользователей идут открытым текстом, и записью в контрольный след;
  - служебная учётная запись — логин и пароль; пароль хранится как секрет (INV-21);
  - базовый DN и фильтр поиска пользователей, например «члены группы KE-Users»;
  - домен — для логинов вида «DOMAIN\login» и «login@domain»;
  - организация сотрудников: одна для всего подключения или по значению атрибута, например company → код организации;
  - сопоставление атрибутов (BR15).

  Кнопка «Проверить подключение» проверяет связь и служебную учётную запись, показывает, сколько пользователей найдёт фильтр, и первых 10 из них с сопоставленными атрибутами.
- **F-14.BR15** — Сопоставление атрибутов AD по умолчанию, администратор может его изменить:

  | Реквизит KE | Атрибут AD |
  |---|---|
  | логин | sAMAccountName |
  | фамилия, имя, отчество | sn, givenName, middleName |
  | e-mail, телефон | mail, telephoneNumber |
  | должность | title |
  | подразделение | department (BR18) |
  | внешний идентификатор — ключ синхронизации | objectGUID |
  | табельный номер — для связи с 1С:ЗУП | employeeID (BR28) |

  Для FreeIPA и ALD Pro: логин ← uid; фамилия, имя ← sn, givenName; отчество — не сопоставлено; e-mail, телефон ← mail, telephoneNumber; должность ← title; подразделение — не сопоставлено; внешний идентификатор ← ipaUniqueID; табельный номер ← employeeNumber. Для OpenLDAP — то же, но внешний идентификатор ← entryUUID. [PROPOSAL]

  Логин учётной записи из каталога в KE — «логин@домен», например «ivanov@pharma.local»: так совпадение логинов в двух доменах не мешает. Пользователь вводит логин в любой форме BR2. Учётная запись каталога связана с учётной записью KE по внешнему идентификатору, а не по логину. Если каталог отдал логин уволенного человека новому сотруднику, у новой учётной записи KE к логину добавляется «~2», «~3»: логин не переиспользуется (INV-26), а человек входит тем же доменным логином. Логин учётной записи SSO строится так же из утверждения провайдера (BR23). [PROPOSAL]
- **F-14.BR16** — Вход учётной записи LDAP-AD:
  - KE проверяет пароль в каталоге при каждом входе и не хранит его;
  - если каталог недоступен, войти нельзя, система сообщает: «Сервер каталога недоступен, попробуйте позже». Локальные учётные записи при этом работают;
  - при входе KE проверяет состояние учётной записи в каталоге: отключённая в каталоге не входит сразу, ещё до синхронизации;
  - пароль доменной учётной записи меняют в домене, не в KE.
- **F-14.BR17** — Синхронизация с каталогом идёт по расписанию (по умолчанию раз в 60 мин; 15 мин – 24 ч) и по кнопке «Синхронизировать сейчас». За один проход она:
  - находит пользователей по фильтру;
  - создаёт и обновляет сотрудников по ключу — внешнему идентификатору — только в организациях, где ведущая система — каталог. В остальных организациях сотрудников не создаёт, а связывает учётную запись с существующим сотрудником (BR28);
  - создаёт учётные записи LDAP-AD для пользователей, которые состоят хотя бы в одной сопоставленной группе [B3-10a];
  - назначает и снимает роли по сопоставлению групп (BR19);
  - отключает учётные записи, которые в каталоге отключены, удалены или вышли из фильтра. Если ведущая система сотрудника — каталог, сотрудник становится «Уволен» [B3-11a];
  - снова включает учётную запись, которую отключила синхронизация, если в каталоге её включили. Если ведущая система сотрудника — каталог и сотрудник стал «Уволен» синхронизацией, он снова становится «Работает». Учётную запись, отключённую вручную в KE, синхронизация не включает.
- **F-14.BR18** — Должность ищется в справочнике «Должности» без учёта регистра и пробелов по краям; если не найдена — добавляется (domain-model §2.3). Подразделение ищется по названию среди действующих подразделений организации сотрудника. Подразделений синхронизация с каталогом не создаёт: если подразделение не найдено или найдено несколько с таким названием, поле у сотрудника остаётся пустым, а строка попадает в журнал синхронизации. [PROPOSAL]
- **F-14.BR19** — Сопоставление групп и ролей [S1 ¶24]: группа каталога — по DN, с учётом вложенных групп [PROPOSAL] — даёт одну или несколько ролей KE.
  - Роль из сопоставления помечена у учётной записи «из группы <название>». Её назначает и снимает только синхронизация, вручную её снять нельзя.
  - Роли, назначенные вручную, синхронизация не трогает.
  - Системную роль и роль «Ответственный по работе с ПД» сопоставить с группой нельзя: иначе их выдавал бы любой, кто меняет состав группы в каталоге, в обход F-13.BR30, F-13.BR13 и INV-27. [PROPOSAL]
  - Если синхронизация снимает роль и в роли-согласующем остаётся меньше участников, чем минимум из настройки INV-15, роль всё равно снимается, а администраторы получают уведомление (INV-15).
  - Конфликты прав (F-13.BR34) не останавливают синхронизацию: они попадают в журнал синхронизации и в отчёт F-13.BR42.
- **F-14.BR20** — Защита от массового отключения [PROPOSAL]. Проход ничего не отключает и не снимает роли, если:
  - каталог вернул 0 пользователей;
  - или проход отключил бы больше 10% учётных записей подключения (настройка, 1–100%).

  Остальные изменения проход применяет. Администраторы системы получают уведомление. Отключение выполняется, когда пользователь с правом «Интеграции, каналы уведомлений, клиенты API» подтвердит его в журнале синхронизации. Следующие проходы до подтверждения тоже ничего не отключают и повторного уведомления не шлют; подтверждение применяет отключение по данным последнего прохода.
- **F-14.BR21** — Журнал синхронизаций: начало и конец, подключение, по расписанию или вручную, сколько сотрудников и учётных записей создано, обновлено и отключено, сколько ролей назначено и снято, ошибки по строкам. При ошибке прохода администраторы получают уведомление (F-06). Журнал хранится 365 дней [PROPOSAL]. Изменения сотрудников и учётных записей пишутся в контрольный след от имени «Система (синхронизация: <подключение>)».
- **F-14.BR22** — Конфликт логинов: если логин из каталога уже занят учётной записью другого источника или другого сотрудника, учётная запись не создаётся и не меняется, а строка с причиной попадает в журнал. Администратор решает вручную, например меняет источник локальной учётной записи на LDAP-AD (BR1).

**SSO** (Should) [B3-12a]
- **F-14.BR23** — Протоколы SSO [B3-12a]: OpenID Connect (Keycloak, Blitz Identity Provider, Avanpost, ADFS и другие провайдеры) и Kerberos — сквозной вход для компьютеров в домене Windows или ALD Pro. Настройки провайдера ведёт пользователь с правом «Интеграции, каналы уведомлений, клиенты API», секреты — INV-21. SSO только подтверждает личность [PROPOSAL]:
  - учётная запись должна уже существовать: её создали вручную или синхронизация;
  - KE ищет её по логину из утверждения провайдера; какое утверждение брать, настраивается, например preferred_username или upn;
  - если учётной записи нет или она не активна, система сообщает: «Учётная запись не найдена или отключена. Обратитесь к администратору».
- **F-14.BR24** — Для входа через SSO действуют тайм-аут и наибольшая длительность сессии KE (BR5). Выход из KE не завершает сессию у провайдера. Если сквозной вход в домене не удался, система показывает обычную страницу входа. Как подписывают пользователи SSO — OQ-3 (Архитектор), F-12.

**1С:ЗУП и другие кадровые системы** (Should) [B3-13a]
- **F-14.BR25** — Ведущая система сотрудников и оргструктуры выбирается для каждой организации: «Вручную», «Каталог», «1С:ЗУП» или «API». Пример: «Фарма-1» — из 1С:ЗУП, «Холдинг» — из AD, «Подрядчик-сервис» — вручную. Правила [PROPOSAL]:
  - сотрудников и подразделения организации создаёт и обновляет только её ведущая система: каталог (BR17), 1С:ЗУП (BR27) или API (BR30). У созданных так сотрудников та же ведущая система (F-13.BR9);
  - в любой организации пользователь с правом «Ведение сотрудников» может завести сотрудника вручную или загрузить из файла, например подрядчика, которого нет в кадровой системе. Ведущая система такого сотрудника — «Вручную», синхронизация его не меняет;
  - одно подключение к каталогу может обслуживать несколько организаций (BR14).
- **F-14.BR26** — Подключение к 1С:ЗУП 3.1:
  - адрес публикации информационной базы и учётная запись; пароль хранится как секрет;
  - какие организации ЗУП загружать и в какие организации KE — по ИНН или вручную;
  - расписание — по умолчанию раз в сутки в 03:00 по времени сервера;
  - кнопка «Проверить подключение».
- **F-14.BR27** — Из 1С:ЗУП загружаются:
  - подразделения — дерево с наименованиями; ключ — внешний идентификатор; код строит система (F-13.BR3);
  - должности — в справочник «Должности»;
  - сотрудники — ФИО, подразделение, должность, табельный номер, дата приёма, дата увольнения.

  Правила:
  - сотрудник KE создаётся только по основному месту работы; совместительство отдельного сотрудника не создаёт [PROPOSAL];
  - когда наступает дата увольнения, сотрудник становится «Уволен», его учётная запись отключается (F-13.BR10);
  - перевод меняет подразделение и должность;
  - подразделение, расформированное в ЗУП, становится недействующим (F-13.BR5).

  Защита от массового отключения — как BR20.
- **F-14.BR28** — Если ведущая система организации — не каталог, синхронизация с каталогом связывает учётную запись с сотрудником этой организации по табельному номеру. Табельный номер берётся из атрибута каталога, по умолчанию employeeID. Если табельный номер не задан или не найден, учётная запись не создаётся, а строка попадает в журнал как «не сопоставлена». Администратор может вручную выбрать сотрудника для учётной записи.
- **F-14.BR29** — Ведущие реквизиты, если подключены и 1С:ЗУП, и каталог [PROPOSAL]:
  - из ЗУП — ФИО, организация, подразделение, должность, табельный номер, состояние «Работает» или «Уволен»;
  - из каталога — логин, e-mail, телефон, состояние учётной записи;
  - в KE — Telegram, MAX (их меняют сам сотрудник и роль «Ответственный по работе с ПД», F-13.BR13), часовой пояс.

  Реквизиты из ведущей системы в интерфейсе только для чтения (F-13.BR9).
- **F-14.BR30** — Загрузка из файла и API — для кадровых систем, кроме 1С:ЗУП [PROPOSAL]:
  - пользователь с правами «Ведение сотрудников» и «Ведение организаций и подразделений» загружает подразделения и сотрудников из Excel или CSV;
  - ключ — табельный номер внутри организации: сотрудник с существующим номером обновляется, с новым — создаётся;
  - строки с ошибками не загружаются и попадают в отчёт, остальные загружаются (как F-19.BR27);
  - увольнение — колонка «Дата увольнения»;
  - загруженные из файла сотрудники получают ведущую систему «Вручную» (BR25);
  - подразделения в файле: «Код подразделения», «Наименование», «Код родителя». «Код подразделения» — ключ загрузки, он сохраняется как внешний идентификатор подразделения; код подразделения в KE система строит по F-13.BR3.

  Через REST API (F-15) сотрудники и подразделения загружаются по тем же правилам в организации, где ведущая система — «API».

## 7. Интерфейс (для дизайнера)
- **Страница входа:** логин, пароль, кнопка SSO; сообщения BR3; смена временного или истёкшего пароля сразу после входа.
- **Профиль → Пароль** (только локальные): смена пароля с подсказками по политике.
- **Администрирование → Пользователи → учётная запись:** «Сбросить пароль» — окно с временным паролем, показанным один раз, и кнопкой «Копировать»; «Разблокировать»; активные сессии с кнопкой «Завершить».
- **Интеграции → Каталоги:** список подключений, форма подключения, «Проверить подключение» с предпросмотром, сопоставление атрибутов, сопоставление групп и ролей, «Синхронизировать сейчас», журнал синхронизаций с подтверждением отложенного отключения (BR20).
- **Интеграции → SSO, 1С:ЗУП:** формы подключения, проверка, журнал.
- **Справочник «Сотрудники» → «Загрузить из файла»:** шаблон файла, отчёт о загрузке.
- **Настройки системы → Вход и пароли:** параметры BR4, BR5, BR9, BR11.

## 8. Не входит
- Двухфакторная аутентификация: одноразовые коды, токены.
- Вход по сертификату и через КриптоПро (R5a).
- Автоматическое создание учётной записи при первом входе через SSO (BR23).
- Своё хранилище паролей для учётных записей LDAP-AD; смена доменного пароля из KE.
- Создание подразделений из каталога (BR18): оргструктуру даёт 1С:ЗУП, файл или ручное ведение.
- Единый выход (single logout) из провайдера SSO.
- Аутентификация клиентов API — F-15 (токены, NFR-9).
