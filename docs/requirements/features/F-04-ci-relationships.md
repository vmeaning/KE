# F-04. Связи КЕ

> Статус: approved · 2026-10-14 · Приоритет: Must
> Источник: S1 ¶16; S2; P-7; W-3c (весов нет); W-4a (граф — в roadmap); R2-2a; D-1a; domain-model §3.6, §4.3; INV-10; README §5
> Зависит от: F-01, F-19 · Используется в: F-22 (анализ влияния), F-30 (предупреждение зависимых КЕ) · Экраны: появятся у дизайнера

## 1. Цель
Связь между КЕ записывается один раз и видна с обеих сторон, а система не даёт завести бессмысленные связи. Фича решает задачу, если:
- связь «ИС Договоры» *входит в* «Корпоративная ИС», созданная из карточки «ИС Договоры», сразу видна в карточке «Корпоративной ИС» как «Включает в себя» [S1 ¶16];
- анализ влияния (F-22) опирается на направление влияния, заданное в типе связи.

## 2. Роли и права
Права по умолчанию (README §5): строки «Связи КЕ» и «Настройка… ведение типов связей».

| Роль | Видит связи | Создаёт и удаляет связи | Ведёт типы связей |
|---|---|---|---|
| Администратор системы | ✓ | ✓ | ✓ |
| Администратор конфигурации | ✓ | — | ✓ |
| Менеджер конфигураций | ✓ | ✓ | — |
| Инженер | ✓ | ✓ | — |
| Согласующий, Аудитор, Наблюдатель | ✓ | — | — |

Пользователь видит связь, только если видит обе КЕ (BR19).

## 3. User stories
Роли настраиваются (README §5), поэтому story называет право, а не роль. Какие роли получают право по умолчанию — таблица §2 [ревью ВП 2026-10-14].

- **F-04.US1** — Как пользователь с правом ведения справочника «Типы связей», я хочу вести справочник типов связей — прямое и обратное названия, направление влияния, допустимые пары, признак иерархии, — чтобы связи в реестре были однозначными.
- **F-04.US2** — Как пользователь с правом «Связи КЕ», я хочу связать КЕ с другой КЕ из карточки любой из них, чтобы связь сразу появилась в обеих карточках.
- **F-04.US3** — Как пользователь с правом «Связи КЕ», я хочу, чтобы система не давала создать бессмысленную связь — с самой собой, недопустимую пару, цикл, дубль, — чтобы данные о зависимостях были корректными.
- **F-04.US4** — Как пользователь, я хочу видеть связи КЕ по типам, со статусом и критичностью связанных КЕ, чтобы понимать, от чего зависит КЕ и что зависит от неё.
- **F-04.US5** — Как пользователь с правом «Связи КЕ», я хочу удалить ошибочную связь, чтобы она не искажала анализ влияния.
- **F-04.US6** — Как пользователь с правом «Просмотр истории КЕ», я хочу видеть создание и удаление связей в истории обеих КЕ, чтобы восстановить, как менялась конфигурация.

## 4. Бизнес-правила

**Тип связи**
- **F-04.BR1** — Тип связи — запись встроенного справочника «Типы связей» [D-1a, domain-model §3.6]. Атрибуты:
  - код — не меняется [INV-1], формат — INV-24;
  - прямое название, обратное название;
  - описание;
  - направление влияния (BR3);
  - допустимые пары (BR4);
  - признаки «Симметричный», «Иерархический», «Действует».

  Пример: «Входит в» / «Включает в себя».
- **F-04.BR2** — Симметричный тип одинаково читается с обеих сторон:
  - обратное название совпадает с прямым;
  - направление влияния — «взаимная зависимость» или «нет зависимости».

  Пример: «Взаимодействует с».
- **F-04.BR3** — Направление влияния показывает, какая КЕ от какой зависит: отказ или изменение одной затрагивает другую. Его использует анализ влияния (F-22) [domain-model §3.6, W-4a]. Связь читается как «источник — прямое название типа — цель»: источник — КЕ, о которой говорит прямое название (глоссарий). Варианты [ревью ВП 2026-10-14]:
  - **источник зависит от цели** — «1С:Бухгалтерия» (источник) *работает на* «srv-app-01» (цель): отказ сервера затрагивает 1С;
  - **цель зависит от источника** — «ИС Договоры» (источник) *входит в* «Корпоративная ИС» (цель): отказ компонента затрагивает целое;
  - **взаимная зависимость** — отказ любой из двух КЕ затрагивает другую;
  - **нет зависимости** — связь справочная, например «СОП-12» *описывает* «ИС Договоры».

  В форме типа связи варианты показываются словами самого типа. Пример для «Работает на»: «„A“ работает на „B“: A зависит от B».
- **F-04.BR4** — Допустимые пары — список пар «категория или тип источника → категория или тип цели» [S2, P-7]. Пустой список означает, что допустимы любые пары. Пара с категорией охватывает все её типы. Пример: для «Установлено на» допустимы «ПО → Сервер» и «ПО → Рабочее место».
- **F-04.BR5** — Изменение допустимых пар не трогает существующие связи. Перед сохранением система показывает, сколько связей этого типа не соответствуют новым парам. Такие связи остаются, в карточке помечаются «не соответствует допустимым парам» и попадают в показатели качества данных (F-21).
- **F-04.BR6** — В связях иерархического типа циклы запрещены [INV-10]. Пример цикла: A входит в B, B входит в C, C входит в A. Признак «Иерархический» нельзя включить, если связи этого типа уже образуют цикл; система показывает один такой цикл.
- **F-04.BR7** — Изменение направления влияния сразу действует на анализ влияния (F-22). Сами связи не меняются.
- **F-04.BR8** — Тип связи, по которому нет ни одной связи, можно удалить. Иначе его можно только сделать недействующим: новые связи этого типа создать нельзя, существующие остаются.
- **F-04.BR9** — Типы связей ведут роли с правом «ведение типов связей»: по умолчанию администратор системы и администратор конфигурации [README §5, D-2a]. Изменения пишутся в контрольный след как изменение конфигурации (F-11).

**Связь**
- **F-04.BR10** — Связь соединяет источник и цель и имеет тип. Хранится одна запись [domain-model §4.3]. В карточке источника связь показывается под прямым названием типа, в карточке цели — под обратным [S1 ¶16]. Весов у связей нет [W-3c].
- **F-04.BR11** — Связь создаётся из карточки любой из двух КЕ. В списке типов есть и прямые, и обратные названия. Пример: в карточке «Корпоративная ИС» пользователь выбирает «Включает в себя» и КЕ «ИС Договоры». Сохраняется связь «ИС Договоры» *входит в* «Корпоративная ИС». После сохранения связь сразу видна в карточках обеих КЕ.
- **F-04.BR12** — Система не сохраняет связь и объясняет причину, если [INV-10]:
  - источник и цель — одна и та же КЕ;
  - такая связь уже есть: тот же источник, цель и тип. Для симметричного типа связь B → A считается той же, что A → B;
  - пара категорий и типов недопустима для типа связи (BR4);
  - связь иерархического типа замыкает цикл; сообщение показывает цепочку;
  - тип связи недействующий;
  - вторая КЕ мягко удалена.
- **F-04.BR13** — Создать или удалить связь может пользователь, у которого есть:
  - право «Связи КЕ» (README §5);
  - право Update на тип КЕ, из карточки которой он действует;
  - доступ на чтение ко второй КЕ — с учётом ограничения по записям.
- **F-04.BR14** — Связь может соединять КЕ разных организаций [R2-2a].
- **F-04.BR15** — У связи есть комментарий до 1 000 символов, его можно менять. Тип, источник и цель связи не меняются: чтобы исправить связь, её удаляют и создают новую.
- **F-04.BR16** — Создание и удаление связи и изменение комментария пишутся в контрольный след и видны в истории обеих КЕ (F-11). Если хотя бы одна из КЕ — в регулируемой категории, нужна причина изменения [P-5, F-08].
- **F-04.BR17** — В v1 связи не входят в baseline [OQ-2] и в контроль изменений [B2-10a]: они создаются и удаляются сразу, без согласования. Изменения связей всё равно видны в истории обеих КЕ (BR16).
- **F-04.BR18** — Связи КЕ в конечном статусе остаются и помечаются статусом этой КЕ [P-7]. Связи мягко удалённой КЕ скрыты, пока её не восстановят (F-03.BR24).
- **F-04.BR19** — Пользователь видит связь, только если видит обе КЕ.
- **F-04.BR20** — В карточке связи сгруппированы по названию типа — прямому или обратному. Для второй КЕ показываются код, наименование, тип, статус с цветом, критичность, организация. У КЕ могут быть тысячи связей (NFR-1), поэтому список связей фильтруется по типу и выводится постранично [S1 ¶14].
- **F-04.BR21** — Из списка связей можно одним действием перейти в карточку связанной КЕ.

## 7. Интерфейс (для дизайнера)
- **Раздел «Связи» в карточке КЕ.**
  - Группы по названию типа.
  - Фильтр по типу связи; постраничный вывод.
  - Пометки: связанная КЕ в конечном статусе (BR18); «не соответствует допустимым парам» (BR5).
  - Действия: добавить связь, удалить связь, изменить комментарий, перейти к КЕ.
- **Диалог «Добавить связь».**
  - Выбор типа по прямому или обратному названию.
  - Поиск второй КЕ по коду и наименованию. Предлагаются только КЕ допустимых для этого типа категорий и типов.
  - Комментарий; причина изменения — в регулируемой категории.
  - Сообщения об ошибках из BR12; для цикла — цепочка КЕ.
- **Справочник «Типы связей»** (раздел «Справочники», F-19).
  - Прямое и обратное названия, направление влияния, допустимые пары, признаки. Варианты направления влияния — словами самого типа: «„A“ работает на „B“: A зависит от B» (BR3).
  - При изменении допустимых пар — число несоответствующих связей (BR5).

## 8. Не входит
- Граф связей и карта сервисов — roadmap [W-4a].
- Веса связей [W-3c]. Если позже понадобится моделировать резервирование, к связи можно добавить справочник «Сила зависимости».
- Атрибуты связи, кроме комментария: даты действия, порты, протоколы.
- Связи в baseline [OQ-2] и в контроле изменений [B2-10a].
- Связь КЕ с типом КЕ.
- Автоматическое создание связей. Массовое создание связей через API (F-15) и импорт (F-16) решается в этих фичах.
