# F-23. Аттестация данных владельцами

> Статус: draft · Приоритет: Should
> Источник: P-24, P-28, B4-14a [ВП 2026-10-17]; README §4 (шаблон «Аттестация данных» в «Базовом ИТ-пакете»); глоссарий «Аттестация данных»; domain-model §1 («Виды мероприятий»)
> Зависит от: F-05 · Связано: F-02 (реестр, массовые операции), F-12 (ЭП), F-21 (устаревшие КЕ) · Экраны: появятся у дизайнера

## 1. Цель
Владелец КЕ периодически подтверждает, что карточка актуальна, а если нет — отмечает, что нужно поправить. Так данные CMDB не стареют молча, а в GxP это часть периодического пересмотра. Фича решает задачу, если:
- у каждой КЕ видна дата последнего подтверждения актуальности, и устаревшие КЕ находятся фильтром;
- кампания аттестации по 300 серверам показывает, сколько подтверждено, сколько ждёт и сколько требует правки.

## 2. Роли и права
Аттестация — мероприятие (F-05), права те же. Шаблон «Аттестация данных» задаёт пользователь с правом настройки конфигурации, кампанию запускает пользователь с правом «Создание и настройка мероприятий КЕ», подтверждает — тот, кто может подтвердить мероприятие (F-05.BR15).

## 3. User stories
- **F-23.US1** — Как пользователь, который может подтвердить аттестацию (F-05.BR15), я хочу в одном окне посмотреть поля карточки и ответить «Карточка актуальна» или «Нужны правки», чтобы аттестация занимала минуту [B4-14a].
- **F-23.US2** — Как пользователь с правом «Создание и настройка мероприятий КЕ», я хочу запустить кампанию аттестации для выбранных КЕ и видеть её ход, чтобы привести данные в порядок к проверке.
- **F-23.US3** — Как пользователь, я хочу фильтровать реестр по дате последнего подтверждения актуальности и признаку «Требует правки», чтобы найти устаревшие и сомнительные карточки [P-28].

## 4. Бизнес-правила
- **F-23.BR1** — Аттестация — мероприятие вида «Аттестация данных». Это системная запись справочника «Виды мероприятий» (domain-model §1). Регулярная аттестация задаётся шаблоном — в «Базовом ИТ-пакете» он есть (README §4), — разовая создаётся вручную или кампанией (BR6).
- **F-23.BR2** — Окно подтверждения аттестации [B4-14a]:
  - показывает поля карточки КЕ только для чтения, по группам шаблона карточки. Контактные данные — по INV-28;
  - `[PROPOSAL]` поля видны подтверждающему, даже если у него нет Read на КЕ: без них аттестовать нельзя. Это исключение из F-13.BR28. Подтверждающий — ответственный, подтверждающий мероприятия, их заместитель или руководитель (F-05.BR15);
  - ответ — «Карточка актуальна» или «Нужны правки». Для «Нужны правки» обязателен комментарий: что не так;
  - ЭП — если задана в мероприятии (F-12). В GxP-пакете аттестация входит в периодический пересмотр.

  Ответ задаёт итог выполнения (F-05.BR18): «Карточка актуальна» — «Успешно», «Нужны правки» — «С замечаниями». Реакция на итог — по настройке мероприятия (F-05.BR19).
- **F-23.BR3** — «Карточка актуальна» записывает в КЕ дату последнего подтверждения актуальности — базовое служебное поле, только для чтения (F-01.BR14, domain-model §3.3). Ответ «Нужны правки» дату не меняет. Поле видно в карточке, доступно как колонка и фильтр реестра и используется в показателе «устаревшие КЕ»: не изменялись и не аттестовались N дней (P-28, F-21).
- **F-23.BR4** — «Нужны правки»:
  - КЕ получает пометку «Требует правки» с комментарием, автором и датой. Пометка видна в карточке и доступна как фильтр реестра;
  - `[PROPOSAL]` пометку снимает следующее сохранение карточки пользователем с правом Update или повторная аттестация с ответом «Карточка актуальна»;
  - `[PROPOSAL]` если у подтверждающего есть право Update на КЕ, после подтверждения сразу открывается редактирование карточки.
- **F-23.BR5** — `[PROPOSAL]` Если выполнение аттестации аннулировано (F-05.BR26), дата последнего подтверждения актуальности возвращается к прежней, а пометка «Требует правки», поставленная этим выполнением, снимается.
- **F-23.BR6** — Кампания аттестации — массовое создание разового мероприятия «Аттестация данных» для выбранных КЕ (F-02.BR16) [B2-1b]. `[PROPOSAL]` Номер кампании — номер массовой операции — хранится в каждом созданном мероприятии. Отчёт кампании считается по этим мероприятиям, а не по отчёту массовой операции, который хранится 30 дней (F-02.BR19): сколько мероприятий создано, подтверждено с ответом «Актуальна», с ответом «Нужны правки», ждёт, просрочено; список с фильтрами и выгрузкой в Excel. Отчёт доступен автору кампании и пользователям с доступом к КЕ — каждому в пределах доступных КЕ (F-28.BR11).

## 5. Сценарии приёмки
Пишутся при подготовке ТЗ фазы, в которую войдёт фича (допущение A-9).

## 6. Данные
| Поле | Смысл | Тип (логический) | Обязательное | Правила и ограничения |
|---|---|---|---|---|
| Дата последнего подтверждения актуальности (КЕ) | когда карточку последний раз подтвердили | дата | — | базовое служебное поле, только для чтения; BR3 |
| «Требует правки» (КЕ) | пометка, комментарий, кто, когда | флаг + текст + пользователь + дата-время | — | BR4 |
| Ответ аттестации (выполнение) | Карточка актуальна / Нужны правки | перечисление | да, для вида «Аттестация данных» | BR2 |

## 7. Интерфейс (для дизайнера)
- **Окно подтверждения аттестации:** поля карточки по группам, ответ, комментарий, подпись; на телефоне — так же (F-05.BR23).
- **Карточка КЕ:** дата последнего подтверждения актуальности, плашка «Требует правки» с комментарием.
- **Реестр КЕ:** колонка и фильтр «Дата последнего подтверждения актуальности», фильтр «Требует правки».
- **Отчёт кампании.**

## 8. Не входит
- Подтверждение каждого поля по отдельности (сертификация полей).
- Аттестация связей и документов КЕ.
- Автоматический запуск кампаний по расписанию — для регулярности есть шаблон мероприятия.
