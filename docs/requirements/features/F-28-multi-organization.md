# F-28. Несколько организаций в одной установке

> Статус: draft · Приоритет: Must
> Источник: R15c, R2-2a [PO 2026-10-08]; A-7; domain-model §2.1, §2.6, §4.1; F-02.BR20, BR33; F-04.BR13, BR14, BR19; INV-15
> Зависит от: F-13 · Связано: F-02, F-04, F-05, F-08, F-10, F-11, F-15, F-16, F-18, F-22 · Экраны: появятся у дизайнера

## 1. Цель
Холдинг ведёт КЕ нескольких юрлиц в одной установке: у каждой КЕ есть организация-владелец, пользователи видят КЕ своих организаций, общие КЕ (например, ЦОД холдинга) видны нескольким организациям, а настройка одна на всех [R2-2a]. Фича решает задачу, если:
- пользователь «Фарма-2» без доступа к «Фарма-1» не находит КЕ «Фарма-1» нигде: ни в реестре, ни в поиске, отчётах, виджетах, выгрузках и API;
- общий сервер ЦОД виден обеим организациям, и каждая связывает с ним свои КЕ;
- новое юрлицо подключается без изменения категорий, типов и справочников.

## 2. Роли и права
Организации ведёт пользователь с правом «Ведение организаций и подразделений» (F-13.BR1). Доступ к КЕ организаций даёт ограничение по записям в роли (F-13.BR25), его настраивает пользователь с правом «Пользователи, роли, замещения».

| Роль | Видит КЕ | Ведёт организации |
|---|---|---|
| Администратор системы | всех организаций | ✓ |
| Остальные роли по умолчанию | всех организаций: в «Базовом ИТ-пакете» ограничение ролей — «все организации»; заказчик сужает его сам [PROPOSAL] | — |

## 3. User stories
Роли настраиваются (README §5), поэтому story называет право, а не роль. Какие роли получают право по умолчанию — таблица §2.

- **F-28.US1** — Как пользователь с правом «Пользователи, роли, замещения», я хочу ограничить роль списком организаций, чтобы сотрудники юрлица видели только его КЕ.
- **F-28.US2** — Как пользователь с правом Update на тип КЕ, я хочу отметить, для каких ещё организаций КЕ общая, чтобы их сотрудники видели общий ЦОД и связывали с ним свои КЕ [вопрос 1].
- **F-28.US3** — Как пользователь с правом Update на тип КЕ, я хочу сменить организацию-владельца КЕ, чтобы отразить передачу КЕ другому юрлицу.
- **F-28.US4** — Как пользователь, я хочу фильтровать реестр, мероприятия и отчёты по организации, чтобы работать с данными одного юрлица.
- **F-28.US5** — Как пользователь с правом «Ведение организаций и подразделений», я хочу добавить новое юрлицо холдинга, не меняя настройку категорий, типов и справочников.
- **F-28.US6** — Как пользователь установки с одной организацией, я хочу не выбирать организацию там, где выбора нет, чтобы не делать лишних действий.

## 4. Бизнес-правила

**Что общее, что своё** [R2-2a]
- **F-28.BR1** — Организация — измерение данных, а не отдельная система.
  - **Общее на всю установку:** категории, типы, поля, шаблоны карточек, статусные модели, шаблоны мероприятий, справочники (в том числе сотрудники и подразделения всех организаций, контрагенты), роли, настройки системы, интеграции, каналы уведомлений.
  - **Своё у организации:** КЕ — через организацию-владельца; подразделения и сотрудники.
- **F-28.BR2** — Код КЕ уникален во всей установке, нумерация по шаблону кода — общая [A-7]. Проверка возможных дублей (F-02.BR22) ищет по всем организациям, но недоступные КЕ не раскрывает.

**Организация КЕ**
- **F-28.BR3** — У каждой КЕ ровно одна организация-владелец, она обязательна [R2-2a]. По умолчанию — организация сотрудника пользователя (F-02.BR20). Если в установке одна действующая организация, система подставляет её сама и не показывает выбор организации в форме создания КЕ. [PROPOSAL]
- **F-28.BR4** — «Общая для организаций» — список других действующих организаций, может быть пустым. Организация-владелец в него не входит. Пример: «srv-dc-01» — владелец «Холдинг», общая для «Фарма-1» и «Фарма-2».
- **F-28.BR5** — Фильтр организаций в ограничении роли (F-13.BR25) пропускает КЕ, если в списке роли есть её организация-владелец или одна из организаций «Общая для». Через «Общая для» роль даёт только чтение [вопрос 1]:
  - КЕ видна в реестре, поиске, отчётах; карточка открывается на просмотр;
  - с КЕ можно связать свою КЕ — для этого достаточно чтения второй КЕ (F-04.BR13);
  - КЕ можно выбрать в полях своих КЕ;
  - менять поля и статус, вести мероприятия, документы, ответственных, мягко удалять КЕ можно только через доступ к организации-владельцу.
- **F-28.BR6** — Организацию-владельца меняет пользователь с правом Update на тип КЕ. Поле можно сделать контролируемым, как любое базовое поле (F-01.BR25). При смене:
  - подразделение-владелец очищается (F-02.BR33);
  - если новая организация-владелец была в списке «Общая для», она оттуда убирается;
  - связи, мероприятия, документы, ответственные и история сохраняются;
  - если КЕ после сохранения станет недоступна пользователю, система предупреждает (F-13.BR27);
  - смена пишется в контрольный след; в регулируемой категории нужна причина изменения.
- **F-28.BR7** — Ответственным за КЕ можно назначить работающего сотрудника любой организации [вопрос 4]. Пример: инженер управляющей компании отвечает за сервер дочерней. Сотрудник другой организации получает уведомления о КЕ, как любой ответственный.

**Видимость данных**
- **F-28.BR8** — Всё, что привязано к КЕ, видно по доступу к КЕ: мероприятия и их выполнения, документы КЕ, запросы на изменение, baseline, история КЕ, связи (F-04.BR19). Документ, связанный с несколькими КЕ, виден, если доступна хотя бы одна из них; ссылки на недоступные КЕ в нём не показываются (F-10). Документы на типе КЕ видны по праву Read на тип.
- **F-28.BR9** — Задание на согласование получают только участники роли-согласующего, которым КЕ запроса доступна на чтение (F-13.BR26) [вопрос 2]. Пример: в роли «Согласующий GxP» — Петров («Фарма-1») и Сидоров («Фарма-2»); запрос по КЕ «Фарма-1» получает только Петров. Если, кроме инициатора, таких участников нет, запрос передаётся администраторам системы (INV-15). При включении контроля изменений и при изменении состава роли система предупреждает, если для организации, где есть КЕ категории, в роли меньше двух участников с доступом.
- **F-28.BR10** — Контрольный след системы [вопрос 3]: пользователь с правом «Просмотр контрольного следа системы» видит записи о КЕ только по доступным ему КЕ. Записи, не относящиеся к КЕ — конфигурация, пользователи, входы, — видят все с этим правом. Проверка целостности проверяет всю цепочку и показывает только итог (F-11).
- **F-28.BR11** — Списки, поиск, счётчики, виджеты, отчёты, выгрузки, календарь мероприятий и API учитывают только доступные КЕ. Как анализ влияния показывает недоступную КЕ в цепочке зависимостей — F-22.
- **F-28.BR12** — Справочники общие [вопрос 4]: пользователь с разделом «Справочники» видит организации, подразделения и сотрудников всех организаций — ФИО, должность, подразделение, организацию. Контактные данные — по праву «Просмотр контактных данных» (F-13.BR13).
- **F-28.BR13** — Фильтр «Организация» в реестре, мероприятиях и отчётах предлагает только организации, КЕ которых пользователю доступны. Фильтр учитывает и организацию-владельца, и «Общая для».

**Новые и недействующие организации**
- **F-28.BR14** — Роли с ограничением «все организации» видят КЕ новой организации сразу. Роли со списком — только после того, как организацию добавят в список.
- **F-28.BR15** — В недействующей организации нельзя создать КЕ, и её нельзя добавить в «Общая для». Её КЕ остаются доступными по тем же правилам. Деактивация и удаление организации — F-13.BR2.

**Импорт и API**
- **F-28.BR16** — В импорте и API организация КЕ задаётся кодом организации. Ограничение по записям роли пользователя или клиента API действует так же, как в интерфейсе (F-15, F-16).

## 5. Сценарии приёмки
Пишутся при подготовке ТЗ фазы, в которую войдёт фича (допущение A-9).

## 6. Данные
Атрибуты организации — F-13.BR1, domain-model §2.1. Организация-владелец, «Общая для организаций» — базовые поля КЕ (domain-model §4.1). Ограничение роли по организациям — domain-model §2.6. Новых полей фича не добавляет.

## 7. Интерфейс (для дизайнера)
- **Карточка КЕ:** организация-владелец в шапке (F-02); поле «Общая для организаций» — множественный выбор; у КЕ, доступной только как общая, — пометка «Общая КЕ, только просмотр» и нет кнопок изменения.
- **Создание КЕ:** выбор организации скрыт, если действующая организация одна (BR3).
- **Редактор роли:** ограничение по организациям — «все» или список.
- **Фильтр «Организация»** в реестре, мероприятиях, отчётах.
- **Предупреждения:** «КЕ станет вам недоступна» (F-13.BR27); в роли-согласующем меньше двух участников с доступом к КЕ организации (BR9).

## 8. Не входит
- Своя конфигурация у организации: свои типы, поля, справочники, статусные модели, роли (вариант R2-2b/c отклонён).
- Оформление интерфейса по организациям.
- Переключатель «текущая организация»: пользователь видит все доступные организации сразу и сужает их фильтром.
- Передача КЕ другой организации с согласованием принимающей стороны.
- Отдельная база данных на организацию.

## 9. Допущения, решения и открытые вопросы

- **Вопрос 3** — контрольный след и организации (BR10).
