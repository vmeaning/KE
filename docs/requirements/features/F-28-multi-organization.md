# F-28. Несколько организаций в одной установке

> Статус: approved · 2026-10-16 · Приоритет: Must
> Источник: R15c, R2-2a [PO 2026-10-08]; A-7; domain-model §2.1, §2.6, §4.1; F-02.BR20, BR33; F-04.BR13, BR14, BR19; INV-15
> Зависит от: F-13 · Связано: F-02, F-04, F-05, F-08, F-10, F-11, F-15, F-16, F-18, F-22 · Экраны: появятся у дизайнера

## 1. Цель
Холдинг ведёт КЕ нескольких юрлиц в одной установке: у каждой КЕ есть организация-владелец, пользователи видят КЕ своих организаций, общие КЕ (например, ЦОД холдинга) видны нескольким организациям, а настройка одна на всех [R2-2a]. Фича решает задачу, если:
- пользователь «Фарма-2» без доступа к «Фарма-1» не находит КЕ «Фарма-1» ни в реестре, ни в поиске, отчётах, виджетах, выгрузках и API. Исключение — контрольный след для пользователя с правом его просмотра (BR10);
- общий сервер ЦОД виден обеим организациям, и каждая связывает с ним свои КЕ;
- новое юрлицо подключается без изменения категорий, типов и справочников.

## 2. Роли и права
Организации ведёт пользователь с правом «Ведение организаций и подразделений» (F-13.BR1). Доступ к КЕ организаций даёт ограничение по записям в роли (F-13.BR25), его настраивает пользователь с правом «Пользователи, роли, замещения».

| Роль | Видит КЕ | Ведёт организации |
|---|---|---|
| Администратор системы | всех организаций | ✓ |
| Остальные роли по умолчанию | всех организаций: в «Базовом ИТ-пакете» ограничение ролей — «все организации»; заказчик сужает его сам | — |

## 3. User stories
Роли настраиваются (README §5), поэтому story называет право, а не роль. Какие роли получают право по умолчанию — таблица §2.

- **F-28.US1** — Как пользователь с правом «Пользователи, роли, замещения», я хочу ограничить роль списком организаций, чтобы сотрудники юрлица видели только его КЕ.
- **F-28.US2** — Как пользователь с правом Update на тип КЕ, я хочу отметить, для каких ещё организаций КЕ общая, чтобы их сотрудники видели общий ЦОД и связывали с ним свои КЕ [B3-1c].
- **F-28.US3** — Как пользователь с правом Update на тип КЕ, я хочу сменить организацию-владельца КЕ, чтобы отразить передачу КЕ другому юрлицу.
- **F-28.US4** — Как пользователь, я хочу фильтровать реестр, мероприятия и отчёты по организации, чтобы работать с данными одного юрлица.
- **F-28.US5** — Как пользователь с правом «Ведение организаций и подразделений», я хочу добавить новое юрлицо холдинга, не меняя настройку категорий, типов и справочников.
- **F-28.US6** — Как пользователь установки с одной организацией, я хочу не выбирать организацию там, где выбора нет, чтобы не делать лишних действий.

## 4. Бизнес-правила

**Что общее, что своё** [R2-2a]
- **F-28.BR1** — Организация — измерение данных, а не отдельная система.
  - **Общее на всю установку:** категории, типы, поля, шаблоны карточек, статусные модели, шаблоны мероприятий, справочники, роли, настройки системы, интеграции, каналы уведомлений.
  - **Принадлежит организации:** КЕ — через организацию-владельца; подразделения и сотрудники. Справочники «Подразделения» и «Сотрудники» при этом общие: в них видны записи всех организаций (BR12).
- **F-28.BR2** — Код КЕ уникален во всей установке, нумерация по шаблону кода — общая [A-7]. Проверка возможных дублей (F-02.BR22) ищет по всем организациям, но недоступные КЕ не раскрывает.

**Организация КЕ**
- **F-28.BR3** — У каждой КЕ ровно одна организация-владелец, она обязательна [R2-2a]. По умолчанию — организация сотрудника пользователя (F-02.BR20). Если в установке одна действующая организация, система подставляет её сама и не показывает выбор организации в форме создания КЕ.
- **F-28.BR4** — «Общая для организаций» — список других действующих организаций, может быть пустым. Организация-владелец в него не входит. Пример: «srv-dc-01» — владелец «Холдинг», общая для «Фарма-1» и «Фарма-2».
- **F-28.BR5** — Фильтр организаций в ограничении роли (F-13.BR25) пропускает КЕ, если в списке роли есть её организация-владелец или одна из организаций «Общая для». Что даёт доступ через «Общая для», задаёт настройка системы «Доступ к общим КЕ» [B3-1c]:
  - **«Только просмотр»** — по умолчанию [B3-16a];
  - **«По правам роли»** — как к своей КЕ: роль даёт Read, Update, Delete на тип, и они действуют.

  При значении «Только просмотр»:
  - КЕ видна в реестре, поиске, отчётах; карточка открывается на просмотр;
  - с ней можно связать свою КЕ — из карточки своей КЕ: для этого достаточно чтения второй КЕ (F-04.BR13);
  - КЕ можно выбрать в полях своих КЕ;
  - менять поля и статус, вести мероприятия, документы, ответственных и связи из её карточки, мягко удалять КЕ можно только через доступ к организации-владельцу, даже если роль даёт Update или Delete на тип (F-13.BR26).
- **F-28.BR6** — Организацию-владельца меняет пользователь с правом Update на тип КЕ. Поле можно сделать контролируемым, как любое базовое поле (F-01.BR25). При смене:
  - подразделение-владелец очищается (F-02.BR33);
  - если новая организация-владелец была в списке «Общая для», она оттуда убирается;
  - связи, мероприятия, документы, ответственные и история сохраняются;
  - если КЕ после сохранения станет недоступна пользователю, система предупреждает (F-13.BR27);
  - смена пишется в контрольный след; в регулируемой категории нужна причина изменения.
- **F-28.BR7** — Каких сотрудников можно назначить ответственными, задаёт настройка «Видимость сотрудников других организаций» (BR12) [B3-4c]:
  - «Все организации» — работающего сотрудника любой организации. Пример: инженер управляющей компании отвечает за сервер дочерней;
  - «Только свои организации» — только сотрудников организаций, которые пропускает ограничение ролей пользователя.

  Сотрудник другой организации получает уведомления о КЕ, как любой ответственный.

**Видимость данных**
- **F-28.BR8** — Всё, что привязано к КЕ, видно по доступу к КЕ: мероприятия и их выполнения, документы КЕ, запросы на изменение, baseline, история КЕ, связи (F-04.BR19). Документ, связанный с несколькими КЕ, виден, если доступна хотя бы одна из них; ссылки на недоступные КЕ в нём не показываются (F-10). Документы на типе КЕ видны по праву Read на тип. Исключение — ответственный за мероприятие, подтверждающий, их заместители и руководители видят мероприятие в «Моих делах» и без доступа к КЕ (F-13.BR28) [B4-4, порция 4].
- **F-28.BR9** — Задание на согласование получают только участники роли-согласующего, которым КЕ запроса доступна на чтение (F-13.BR26) [B3-2a]. Пример: в роли «Согласующий GxP» — Петров («Фарма-1») и Сидоров («Фарма-2»); запрос по КЕ «Фарма-1» получает только Петров. Если, кроме инициатора, таких участников нет, запрос передаётся администраторам системы (INV-15). «Участник с доступом к организации» — активный участник роли, у которого хотя бы одна роль даёт Read хотя бы на один тип категории и пропускает эту организацию. Минимум из INV-15 считается по всем участникам роли. Дополнительно:
  - в настройках контроля изменений категории видно, сколько участников с доступом есть для каждой организации, где есть КЕ категории; меньше минимума из настройки INV-15 — с пометкой;
  - система предупреждает об этом при включении контроля изменений и при сохранении состава роли-согласующего или её ограничения по записям.
- **F-28.BR10** — Контрольный след системы виден пользователю с правом «Просмотр контрольного следа системы» целиком, по всем организациям, без учёта ограничения по записям [B3-3b]. Контактные данные в записях скрыты, если у пользователя нет права на их просмотр (F-13.BR13). История КЕ в карточке видна по доступу к КЕ (BR8).
- **F-28.BR11** — Списки, поиск, счётчики, виджеты, отчёты, выгрузки, календарь мероприятий и API учитывают только доступные КЕ. Как анализ влияния показывает недоступную КЕ в цепочке зависимостей — F-22. Исключение — мероприятия в «Моих делах» ответственного, подтверждающего, их заместителей и руководителей (F-13.BR28) [B4-4, порция 4].
- **F-28.BR12** — Настройка системы «Видимость сотрудников других организаций» [B3-4c]:
  - **«Все организации»** — по умолчанию [B3-16a]: пользователь с разделом «Справочники» видит подразделения и сотрудников всех организаций — ФИО, должность, подразделение, организацию, состояние (F-13.BR13);
  - **«Только свои организации»** — справочники «Подразделения» и «Сотрудники» и списки выбора сотрудника показывают только организации, которые пропускает ограничение ролей пользователя. Если в доступной КЕ уже указан сотрудник другой организации, его ФИО и организация видны в карточке.

  Справочник «Организации» виден целиком при любом значении. Контактные данные — только для роли «Ответственный по работе с ПД» (F-13.BR13).
- **F-28.BR13** — Фильтр «Организация» в реестре, мероприятиях и отчётах предлагает только организации, КЕ которых пользователю доступны. Фильтр учитывает и организацию-владельца, и «Общая для».

**Новые и недействующие организации**
- **F-28.BR14** — Роли с ограничением «все организации» видят КЕ новой организации сразу. Роли со списком — только после того, как организацию добавят в список.
- **F-28.BR15** — В недействующей организации нельзя создать КЕ, и её нельзя добавить в «Общая для». Её КЕ остаются доступными по тем же правилам. Деактивация и удаление организации — F-13.BR2.

**Импорт и API**
- **F-28.BR16** — В импорте и API организация КЕ задаётся кодом организации. Ограничение по записям роли пользователя или клиента API действует так же, как в интерфейсе (F-15, F-16).

## 5. Сценарии приёмки
Пишутся при подготовке ТЗ фазы, в которую войдёт фича (допущение A-9).

## 6. Данные
Атрибуты организации — F-13.BR1, domain-model §2.1. Организация-владелец, «Общая для организаций» — базовые поля КЕ (domain-model §4.1). Ограничение роли по организациям — domain-model §2.6. Фича добавляет две настройки системы:

| Поле | Смысл | Тип (логический) | Обязательное | Правила и ограничения |
|---|---|---|---|---|
| «Доступ к общим КЕ» | что даёт «Общая для организаций» | перечисление: Только просмотр / По правам роли | да | по умолчанию «Только просмотр»; BR5 [B3-1c] |
| «Видимость сотрудников других организаций» | чьих сотрудников видно и можно выбрать | перечисление: Все организации / Только свои организации | да | по умолчанию «Все организации»; BR7, BR12 [B3-4c] |

## 7. Интерфейс (для дизайнера)
- **Карточка КЕ:** организация-владелец в шапке (F-02); поле «Общая для организаций» — множественный выбор; у КЕ, доступной только как общая, при настройке «Только просмотр» — пометка «Общая КЕ, только просмотр» и нет кнопок изменения.
- **Настройки системы:** «Доступ к общим КЕ», «Видимость сотрудников других организаций» — с подсказкой, что меняет каждое значение.
- **Создание КЕ:** выбор организации скрыт, если действующая организация одна (BR3).
- **Редактор роли:** ограничение по организациям — «все» или список.
- **Фильтр «Организация»** в реестре, мероприятиях, отчётах.
- **Предупреждения:** «КЕ станет вам недоступна» (F-13.BR27); в роли-согласующем меньше участников с доступом к КЕ организации, чем минимум из INV-15 (BR9).

## 8. Не входит
- Своя конфигурация у организации: свои типы, поля, справочники, статусные модели, роли (вариант R2-2b/c отклонён).
- Оформление интерфейса по организациям.
- Переключатель «текущая организация»: пользователь видит все доступные организации сразу и сужает их фильтром.
- Передача КЕ другой организации с согласованием принимающей стороны.
- Отдельная база данных на организацию.
