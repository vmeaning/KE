## Вопросы порции 3
Ответ — строкой вида «1a, 2a, 3b…». Рекомендованный вариант стоит первым. После ответа решения получат коды `B3-n` и попадут в discovery §9, а пометки «[вопрос N]» в файлах фич заменятся кодами решений.

**Несколько организаций (F-28)**
1. **Что даёт «Общая для организаций»** (F-28.BR5). Пример: сервер ЦОД — владелец «Холдинг», общий для «Фарма-1».
   - a) Только чтение: «Фарма-1» видит сервер, связывает с ним свои КЕ, выбирает его в полях, но не меняет поля, статус, мероприятия, документы. Менять может только организация-владелец. **(рекомендую: у общей КЕ один хозяин, нет конфликтов правок)**
   - b) Полный доступ по правам роли, как к своей КЕ.
2. **Кто получает задание на согласование в холдинге** (F-28.BR9). Роль-согласующий одна на категорию, а в ней согласующие разных юрлиц.
   - a) Только участники роли, которым КЕ запроса доступна. Согласующий «Фарма-2» не согласует изменения «Фарма-1». Если таких участников нет — запрос уходит администраторам (INV-15). **(рекомендую)**
   - b) Все участники роли, независимо от доступа к КЕ.
3. **Контрольный след системы и организации** (F-28.BR10).
   - a) Записи о КЕ — только по доступным КЕ; записи о конфигурации, пользователях, входах — всем с правом. Аудитор «Фарма-1» не видит изменений КЕ «Фарма-2». **(рекомендую)**
   - b) Весь след — всем с правом «Просмотр контрольного следа».
4. **Сотрудники других организаций** (F-28.BR7, BR12).
   - a) Видны всем пользователям с разделом «Справочники»: ФИО, должность, подразделение, организация. Ответственным за КЕ можно назначить сотрудника любой организации. **(рекомендую: в холдинге общие службы ИТ)**
   - b) Видны только сотрудники организаций из ограничения ролей пользователя. Тогда ответственным за КЕ нельзя выбрать сотрудника чужой организации.

**Оргструктура, роли и права (F-13)**

5. **Кто видит контактные данные** — e-mail, телефон, Telegram, MAX сотрудников и контакты контрагентов (F-13.BR13). Это персональные данные (152-ФЗ).
   - a) Отдельное право «Просмотр контактных данных». По умолчанию оно у всех ролей, кроме Наблюдателя. Без права видны ФИО, должность, подразделение. Право действует и на контактных лиц контрагентов — это дополняет утверждённую F-19. **(рекомендую: заказчик сам решает по своей политике ПДн)**
   - b) Контакты видят все пользователи, отдельного права нет.
   - c) Право есть, но по умолчанию — только у администратора системы и менеджера конфигураций.
6. **Раздел «Справочники» у ролей по умолчанию** (F-13.BR23). Видеть записи справочников нужно, например, чтобы найти местоположение или контрагента.
   - a) У всех ролей по умолчанию, кроме Наблюдателя. **(рекомендую)**
   - b) У всех ролей.
   - c) Только у ролей, которые ведут хотя бы один справочник.
7. **Самоназначение прав администратором** (F-13.BR36): меняет права своей роли, назначает роль себе, включает себя в согласующие.
   - a) Разрешено, но запись в следе помечается «самоназначение», остальные администраторы и аудиторы получают уведомление, есть отчёт. **(рекомендую: прозрачно и не блокирует установку с одним администратором)**
   - b) Запрещено: свои права меняет только другой администратор. В установке с одним администратором придётся заводить второго.
   - c) Без контроля, только обычная запись в следе.
8. **Опасные сочетания прав** (F-13.BR34, BR35). Список из четырёх пар — в BR34, поправь его, если нужно.
   - a) Предупреждение с объяснением риска; сохранить можно после подтверждения; пометка в следе; отчёт о конфликтах. **(рекомендую: маленьким IT-службам нужна гибкость, крупным — прозрачность)**
   - b) Запрет: роль или назначение с конфликтом не сохраняется.
   - c) Не проверять.
9. **Кто назначает заместителя** (F-13.BR45).
   - a) Пользователь — себе, администратор — любому. **(рекомендую: перед отпуском человек делает это сам, без заявки администратору)**
   - b) Только администратор.

**Аутентификация и синхронизация (F-14)**

10. **Кто создаёт учётные записи из каталога** (F-14.BR17).
    - a) Синхронизация: сразу для всех членов сопоставленных групп. Права видны до первого входа, отчёт для пересмотра доступов полный. **(рекомендую)**
    - b) Учётная запись создаётся при первом входе пользователя, роли — по группам.
11. **Учётная запись отключена в каталоге, а 1С:ЗУП не подключена** (F-14.BR17).
    - a) Учётная запись отключается, сотрудник становится «Уволен». Его КЕ попадут в отчёт о выбывших (F-02.BR43), и их передадут другому. **(рекомендую)**
    - b) Отключается только учётная запись; состояние сотрудника меняют вручную. Риск — ответственные, которых уже нет, останутся незамеченными.
12. **Протоколы SSO** (F-14.BR23, приоритет Should).
    - a) OpenID Connect (Keycloak, Blitz Identity Provider, Avanpost, ADFS) и Kerberos — сквозной вход для компьютеров в домене Windows или ALD Pro. **(рекомендую: покрывает и «вход без пароля в домене», и корпоративные IdP)**
    - b) Только OpenID Connect.
    - c) OpenID Connect, SAML 2.0 и Kerberos — шире, но дороже в разработке и тестировании.
13. **Как подключаем 1С:ЗУП** (F-14.BR26–BR30, приоритет Should).
    - a) Встроенный коннектор KE к стандартному интерфейсу OData 1С:ЗУП 3.1: администратор вводит адрес и учётную запись, KE забирает данные по расписанию. Для других кадровых систем — загрузка из Excel или CSV и REST API. **(рекомендую: коробка — без программиста 1С у заказчика)**
    - b) Только файл и API: выгрузку из ЗУП заказчик делает сам.
    - c) Мы поставляем внешнюю обработку для 1С, которая отправляет данные в KE через API. Нужна компетенция 1С в команде.
14. **Забытый пароль локальной учётной записи** (F-14.BR11). Локальные учётные записи — в основном администраторы и подрядчики, остальные входят через каталог.
    - a) Сбрасывает администратор: система показывает временный пароль один раз, при входе его надо сменить. **(рекомендую: проще и безопаснее в закрытом контуре)**
    - b) Плюс самостоятельный сброс по ссылке на e-mail, ссылка действует 30 мин.

Кроме вопросов, на утверждение — пометки `[PROPOSAL]` в F-13, F-14, F-28 и новые инварианты INV-25…INV-27 в доменной модели.

## Как читать файл фичи
- User story называет право, а не роль: «Как пользователь с правом «Экспорт реестра»…». Роли настраиваются (README §5), а роли по умолчанию с этим правом перечислены в таблице §2 файла [ревью ВП 2026-10-14]. Так же записан шаблон `.claude/skills/analyst/templates/feature.md`.
- `F-NN.USm` — user story, `F-NN.BRk` — бизнес-правило. Ссылка на правило другой фичи — полным ID, например `F-01.BR23`.
- В квадратных скобках — источник правила: `[S1 ¶N]`, решение ВП, `INV-n`, раздел доменной модели.
- `[PROPOSAL]` — предложение Аналитика без источника: ВП утверждает его вместе с порцией.
- `[B2-Nx]` — правило следует решению ВП по вопросу N порции 2 (таблица выше).
- `[вопрос N]` — правило зависит от ответа ВП на вопрос N порции 3 (список выше).
