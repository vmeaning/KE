## 1. Видение

KE — коробочная on-prem система управления конфигурационными единицами IT-службы по принципам ITIL.
- **Учёт КЕ любых типов** — их статусов, связей, истории и ответственных — с настройкой без программирования.
- **Плановые мероприятия по КЕ** (регулярные и разовые) — с уведомлениями, задачами в таск-трекерах и подтверждением выполнения.
- **Готовность к регулируемой среде**: контроль изменений, электронная подпись, неизменяемый контрольный след, baseline. Для фармы (GxP, GAMP 5) соответствие включается поставляемым GxP-пакетом конфигурации, а не отдельной версией продукта.
- **Два слоя**: базовый слой (продукт) и конфигурационный слой (настройки заказчика). Конфигурация переносится пакетами между установками и сохраняется при обновлениях.
- **Самостоятельная интеграция заказчика**: AD/LDAP, кадровые системы, таск-трекеры, собственные системы через API.

Источники: [S1 ¶3–4, ¶24], [S2], discovery §1.

**Критерии успеха v1**:
1. IT-служба заказчика без участия поставщика настраивает категории и типы КЕ (или берёт их из отраслевого пакета), а затем загружает существующий реестр из Excel.
2. Ни одно обязательное регулярное мероприятие не просрочено без уведомления ответственного.
3. Фарм-заказчик проходит инспекцию по разделу «Компьютеризированные системы» с выгрузками из KE: реестр КС, история изменений с подписями, история проведения регулярных и разовых мероприятий (в том числе валидационных) со ссылками на документы о результатах, периодические пересмотры.

## 2. Границы

**Входит:**
- КЕ, категории и типы, конструктор карточек, справочники;
- статусные модели, связи, анализ влияния;
- мероприятия, уведомления, интеграция с таск-трекерами;
- контроль изменений, baseline, ЭП, контрольный след;
- документы;
- роли, права, несколько организаций;
- аутентификация через AD/LDAP и SSO;
- API, импорт данных, экспорт и импорт конфигурации, отраслевые пакеты;
- главная страница с виджетами, качество данных.

**Не входит** (сознательно):
- Service Desk: обращения, инциденты, проблемы — только ссылки на внешнюю систему (F-26);
- исполнение работ: закупка, приёмка, наряды — это таск-трекер (R13a);
- автообнаружение (сканирование сети) — данные приходят от внешних систем через API (discovery §5);
- учёт лицензий ПО и финансовый учёт активов — через настраиваемые поля и контролируемые даты;
- нативное мобильное приложение — есть адаптивная карточка (P-22);
- УНЭП/КЭП через КриптоПро — позже, как опция (R5a);
- Telegram и MAX — следующей очередью (R11a);
- настраиваемые пользователем дашборды и графики — следующей очередью (discovery §5.4);
- многоязычные справочные данные (A-4).

## 3. Пользователи

| Пользователь | Задачи |
|---|---|
| **Администратор системы** | пользователи, роли, оргструктура, интеграции, каналы уведомлений, настройки системы |
| **Администратор конфигурации** | категории, типы, шаблоны карточек, статусные модели, справочники, шаблоны мероприятий, пакеты конфигурации [S2] |
| **Менеджер конфигураций** (руководитель технической службы) | ведёт реестр, утверждает ключевые действия, управляет baseline, отвечает за качество данных [S1 ¶17], [S2] |
| **Инженер / ответственный** | ведёт свои КЕ, выполняет и подтверждает мероприятия, предлагает изменения |
| **Согласующий** | согласует или отклоняет запросы на изменение [S1 ¶22–23] |
| **Аудитор** (служба качества, инспектор) | только чтение, включая историю КЕ и контрольный след (P-21) |
| **Наблюдатель** | только чтение реестра в пределах своих типов КЕ |
| **Сотрудник без учётной записи** | получает уведомления как ответственный, в систему не входит (R7a) |
| **Внешняя система** (клиент API) | читает и обновляет КЕ, получает события [S1 ¶24] |

Все роли настраиваемые. Перечисленные — роли по умолчанию в «Базовом ИТ-пакете».

## 8. Допущения

- **A-1.** Основная работа — на компьютере. На телефоне нужны просмотр карточки и подтверждение мероприятия.
- **A-2.** KE не заменяет Service Desk и таск-трекер: работы исполняются там, а KE хранит план, факт и подтверждение.
- **A-3.** Пароли и секреты самих КЕ (учётки серверов и т.п.) в KE не хранятся.
- **A-4.** Локализация в v1 — тексты интерфейса. Записи справочников хранятся на одном языке.
- **A-5.** Реестр российского ПО — см. NFR-5.
- **A-6.** Контуры заказчиков могут быть без интернета, поэтому установка и обновление работают офлайн (NFR-13).
- **A-7.** Код КЕ уникален во всей установке, а не внутри организации: так проще для API и общих КЕ.
- **A-8.** Контрольный след хранится без автоматического удаления. Политику архивирования определяет заказчик.
- **A-9.** Сценарии приёмки пишутся перед фазой, а не заранее на весь продукт: так они не устаревают до реализации.
- **A-10.** Часовой пояс пользователя задаётся в профиле, по умолчанию — часовой пояс сервера.
