# Глоссарий KE

> Статус: **draft** · 2026-10-08 · Аналитик
> Один термин — одно значение. Все документы, задачи, тексты интерфейса и код используют эти термины. Колонка «Не использовать» — синонимы, которые запрещены, потому что вносят путаницу.
> Код — английский идентификатор для домена и кода.

## 1. Конфигурационные единицы и их настройка

| Термин | Код | Определение | Не использовать | Пример |
|---|---|---|---|---|
| **Конфигурационная единица (КЕ)** | `ConfigurationItem`, `CI` | Учитываемый объект инфраструктуры или сервиса с собственным жизненным циклом: ИС, сервер, оборудование, ПО, документ, ЗИП и т.п. | актив, объект, запись | ИС «Договоры», сервер `srv-db-01` |
| **Категория КЕ** | `CICategory` | Верхний уровень классификации. Задаёт общие поля, статусную модель, мероприятия по умолчанию и настройки контроля изменений для всех своих типов | группа КЕ, класс | «Компьютеризированная система», «Оборудование» |
| **Тип КЕ** | `CIType` | Вид КЕ внутри категории. Добавляет свои поля и мероприятия к полям и мероприятиям категории | вид КЕ, подкатегория | «ЛИМС», «SCADA» в категории «Компьютеризированная система» |
| **Шаблон карточки** | `CardTemplate` | Состав и расположение полей и элементов оформления карточки КЕ для типа: поля категории плюс поля типа | макет, форма типа, карточка типа | — |
| **Базовое поле** | `BaseField` | Поле, которое есть у каждой КЕ любого типа. Удалить нельзя | системное поле | Код, Наименование, Статус |
| **Настраиваемое поле** | `CustomField` | Поле, которое администратор добавил в категорию или тип | кастомное поле, атрибут | «Категория GAMP 5» |
| **Код поля** | `fieldCode` | Неизменяемый латинский идентификатор поля. Используется в API, импорте и правилах. Отображаемое название поля можно менять, код — нет | ID поля, алиас | `gamp_category` |
| **Контролируемое поле** | `controlled` | Настраиваемое или базовое поле, изменение которого требует согласования при включённом контроле изменений | критичный реквизит | — |
| **Контролируемая дата** | `trackedDate` | Поле-дата, отмеченное как отслеживаемое: по нему работают уведомления за N дней и подсветка | — | «Дата окончания лицензии» |
| **Архивированное поле** | `archived` | Поле, скрытое из карточки и новых записей. Данные и история сохраняются, поле можно вернуть | удалённое поле | — |
| **Элемент оформления** | `LayoutElement` | Элемент шаблона без данных: группа полей, разделитель, текстовый блок. Удаляется в любой момент | — | группа «GxP», разделитель |
| **Справочник** | `Directory` | Настраиваемый список значений для выбора в полях и настройках | классификатор, словарь | «Критичность», «Виды документов» |
| **Запись справочника** | `DirectoryEntry` | Одно значение справочника: неизменяемый код, название, порядок, цвет, признак «действует» | элемент, значение | `high` / «Высокая» |
| **Системная запись справочника** | `systemEntry` | Запись, от которой зависит логика продукта или пакета. Переименовать можно, удалить или деактивировать — нельзя | — | статус «Выведена из эксплуатации» |
| **Перечисление продукта** | `enum` | Фиксированный список, новое значение в котором требует изменения кода продукта. Справочником не является | — | типы полей, виды каналов уведомлений |
| **Критичность** | `criticality` | Базовое поле КЕ — значение из справочника «Критичность» | важность, приоритет | Высокая / Средняя / Низкая |
| **Местоположение** | `Location` | Запись иерархического справочника мест: площадка → здание → этаж → помещение → рабочее место | размещение | «Корпус 2, помещение 214» |

## 7. Регуляторные термины

| Термин | Определение |
|---|---|
| **GxP** | Общее обозначение норм надлежащей практики: GMP (производство), GDP (дистрибуция), GLP (лаборатории), GCP (клинические исследования), GVP (фармаконадзор) |
| **Компьютеризированная система (КС)** | Комплекс оборудования, ПО, процессов и персонала, выполняющий определённые функции. В KE — категория КЕ из GxP-пакета |
| **GAMP 5** | Руководство ISPE по риск-ориентированной валидации КС. Категории ПО: 1 (инфраструктура), 3 (стандартное), 4 (конфигурируемое), 5 (заказное) |
| **Валидация** | Документальное подтверждение, что КС пригодна для своего назначения. Включает квалификации IQ, OQ, PQ (установка, функционирование, эксплуатационные характеристики) |
| **Периодический пересмотр** | Регулярная оценка, что валидированная КС остаётся в валидированном состоянии (Annex 11 §11) |
| **ALCOA+** | Принципы целостности данных: записи атрибутируемы, разборчивы, одновременны, оригинальны, точны, а также полны, последовательны, долговечны и доступны |
| **Annex 11** | Приложение 11 к GMP ЕС «Компьютеризированные системы». Аналог — приложение 11 Правил GMP ЕАЭС (Решение Совета ЕЭК № 77) |
| **21 CFR Part 11** | Требования FDA к электронным записям и электронным подписям |
